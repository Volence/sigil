## THE PIVOT — a load-bearing brief recon error (surfaced exactly as P1 was meant to)

The brief states the 12 exception stubs port via `raise_error`, and that a bare
opts=0 `__ErrorMessage` stub's expansion "is EXACTLY what `raise_error` lowers to
today (diag.rs raise_tail:507-544)". **It is not.** Re-derived from the real
listing (`s4.debug.lst`, BusError at `5E5AA`) and from an existing `raise_error`
site (`sound_api.emp:324` → `Sound_PlaySFX` at `7FF6`):

| | prefix before `jsr` | source |
|---|---|---|
| `__ErrorMessage` stub (the 12 vectors) | **NONE** — starts at `jsr (handler).l` (`4EB9…` at 5E5AA) | error_handler.asm via debugger.asm:526 |
| `raise_error` (diag `raise_tail`) | **`pea *(pc)` (487A FFFE) + `move.w sr,-(sp)` (40E7) = 6 bytes** | diag.rs raise_tail steps 4-5; proven at 7FF6/7FFA |

The reason is real, not a bug: an exception **vector** is entered by the CPU's
hardware exception frame (SR + PC already pushed), so `__ErrorMessage` must NOT
push them. `raise_error` is a **deliberate** raise from normal code, so it
SIMULATES the frame (`pea`/`move.w sr`). The two are byte-different by exactly
those 6 bytes, and both are correct for their context. A bare `raise_error "BUS
ERROR"` at an exception vector would be **+6 bytes** wrong at the front.

**P1 verdict (the brief's literal probe): FAILS as stated.** This is the probe
doing its job — "prove … before leaning on it." The port therefore needs an
**exception-context** diag form that omits the frame push. This is the tranche's
real demanded feature (a superset of the brief's "options form").

## THE DESIGN — `raise_exception` (the `__ErrorMessage` counterpart)

New construct, sibling to `raise_error`/`assert` in the diag family:

```
raise_exception "<fstring>" [, <flag>]...
```

Lowers to the exception-vector shape (NO frame simulation, the CPU supplied it):

    [arg pushes, reverse token order]      ; empty for the fixed-string stubs
    jsr  (MDDBG__ErrorHandler).l
    dc.b <encoded fstring + $00 terminator>
    dc.b <flag byte>                        ; opts | _eh_return($20) | align($80 iff even offset)
    [dc.b $00 pad iff flag landed even]
    jmp  (MDDBG__ErrorHandler_PagesController).l

vs `raise_error`, which additionally emits the `.raise` self-label + `pea
self(pc)` + `move.w sr,-(sp)` before the arg pushes. The exception form needs no
self-label (there is no `pea self(pc)`).

**Parity is unchanged.** Every instruction preceding the message is word-sized
(even), so the flag byte's offset parity = `message.len() % 2` regardless of the
prefix length — the existing `exit_flag_bytes` derivation carries over verbatim.
Worked BusError (debug): jsr(6) + "BUS ERROR"+$00 (10, even) → flag at even → `$A1`
(`$01|$20|$80`) + `$00` pad + jmp(6) = 24 bytes; `5E5AA+24 = 5E5C2 = AddressError`.
Re-derived byte-for-byte against the listing. ✓

### Macro-port rule answers (`__ErrorMessage` is the donor macro)

- **Wrong-input scan.** The donor takes a raw `opts` int expression
  (`_eh_default|_eh_address_error`). The closed vocabulary here is the
  error-handler flag set (debugger.asm:114-116). Modeled as **named flags**, so a
  caller cannot pass a bogus bit; the donor's int consts become implementation
  detail, drift-locked to the `.asm` truth by the TDD vector below.
- **Flag vocabulary — DELIBERATELY MINIMAL: `address_error` → `$01` only.** The
  other two donor flags are excluded ON PURPOSE, and this is a reviewable call:
  `_eh_show_sr_usp` ($02) is the GLOBAL config default (`_eh_default`, driven by
  `DEBUGGER__SHOW_SR_USP`), not a per-site flag; `_eh_hide_caller` ($04) is "for
  SGDK and C/C++ projects" (debugger.asm:116) — neither is meaningfully per-message
  in this engine (zero site demand). The macro-port taste gate says don't expose
  knobs the domain doesn't use. `address_error` IS per-site ("this vector is a
  bus/address error — show the Address field"), used by exactly 2 of 12. An
  unknown flag name is a comptime error listing the accepted set; the set grows
  if a real per-site demand appears (ledger, don't pre-build). **Reported as a
  design decision for the overseer — the brief said "minimal"; this is the
  minimal reading. If the overseer wants the full closed set exhaustively, it is
  a 2-line table addition.**
- **Guard upgrade.** The donor's `opts` is a free int add; the named-flag form
  makes an out-of-set flag unrepresentable (comptime error) instead of silently
  OR-ing a wrong bit into the flag byte.
- **First-consumer duty.** `raise_exception` is the first (and, corpus-wide, only)
  consumer of the exception-vector diag shape. Its interface is designed here for
  good; there is no int passthrough.
- **Taste.** `raise_exception "BUS ERROR", address_error` reads as what it is; the
  AS twin keeps `__ErrorMessage "BUS ERROR", _eh_default|_eh_address_error`
  (lockstep is byte-level, not text-level).

### The two-arg `consoleprogram` rejection STAYS (parser.rs:1913-1920)

`raise_error`/`raise_exception` now accept a trailing comma **iff** the next token
is a known flag name. Any other second arg (a program label — the genuine
`consoleprogram` form, gap-ledger demand 0) keeps the existing steering error.
The distinction is the closed flag vocabulary: known flag → options form; else →
`consoleprogram` out-of-scope error. A negative probe pins BOTH directions.

### Should `raise_error` (deliberate) also get the options form?

The flag-parsing + opts-threading is SHARED, so `raise_error` inherits the options
form for free. No current corpus site uses it (the 2 demanded sites are exception
vectors → `raise_exception`). Kept available + symmetric; not exercised by the
port. `assert` passes opts=0 (its exit flag stays bare `_eh_return`, unchanged).
