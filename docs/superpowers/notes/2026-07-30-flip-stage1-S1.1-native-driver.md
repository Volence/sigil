## Answer to CHECKPOINT-1's question — which of the 14 first-time placements fought?

**None fought at the placement level.** BG, BG_ANIM, CAMERA, CORE, DPLC,
ENTITY_WINDOW, LOAD_OBJECT, OBJDEFS, PARALLAX, PLANE_BUFFER, SECTION, SPRITES,
TILE_CACHE, VECTORS all placed + cross-seam-linked cleanly at their `pins` bases
once the shared RESOLVER infrastructure was built. The fights were SYSTEMIC (mixed
open-program semantics), shared by all 52 modules, not per-region:

1. `build_program` is a CLOSED pure-`.emp` resolver — reported every AS-residual
   symbol (SYSTEM_STACK, RAM labels) as an error → needed the open variant.
2. Comptime build defines the `.emp` reads as VALUES: SOUND_DRIVER_ENABLED=1,
   DEBUG=shape, SOUND_DEBUG_HOTKEYS=0, SOUND_DBG_MIRROR=0, GAME_CAMERA_JUMP_LOCK=1.
3. Ambient injection is SHALLOW (one `use` level): a consumer of `sst` got the
   `Sst` struct but not `types.ObjRoutine` it references; a `List` import of a
   derived const (`DMA_TOTAL_SLOTS`) missed its siblings; a pub fn calling a PRIVATE
   sibling (`vdp_comm`→`target_bits`) missed the private. Fix (driver-side, in-memory,
   byte-neutral — comptime items emit nothing): blanket every module with a glob of
   all 11 pure-comptime helpers + publicize the helpers' private comptime items.
4. Per-module `embed_base` (two conflicting `embed(...)` conventions — see above).
5. `rename` module-qualifies pub-proc labels; the AS side references them bare →
   skip rename for the mixed build.
6. `objdef.emp` imports `engine.system.constants` but the header id is
   `engine.constants` — a lone aeon id/path typo; reconciled with an in-memory
   manifest alias (no aeon edit).
7. COMPRESSION_SELFTEST has NO internal DEBUG guard (the caller includes it only at
   DEBUG=1) → placed in the debug shape only.
8. The internal keystones player_common / test_player / test_enemy are
   UNCONDITIONALLY AS-included (no gate) → their `.emp` byte sections are dropped
   (AS owns them; labels resolve against the AS twin).
9. OBJDEFS specifically: its module has no `in <section>`, so its `pub data` lands
   in the default `"text"` section — mapped to the OBJDEFS region, guarded by a
   "exactly one non-empty `text` section" assertion so no stray defaulted-module
   data can corrupt it.

## THE ONE JUDGMENT CALL FOR OVERSEER RATIFICATION — the drift guards

The all-gates flip surfaces a Stage-2 condition EARLY: **4 `.emp` drift guards
`ensure(extern("X") == X_mirror)` reference constants (VRAM_PLANE_B_BYTES) homed
ONLY in a `.asm` twin that is now GATED OFF** (bg.asm), so they fold to Poison
("symbol not defined in this link"), NOT a `Value(0)` drift failure. The driver
partitions: a real `Value(0)` drift stays a HARD failure; a Poison "not defined in
this link" guard is treated INAPPLICABLE (the twin it compares against is gone —
exactly the Stage-2 "guard retires with its twin" state). The whole-ROM byte gate
(native == asl) is the authoritative drift oracle for every USED constant — a
drifted value would change emitted bytes and fail the byte gate. This is NOT a
relaxation of drift DETECTION, but it IS a handling decision on unresolvable-extern
guards — flagged here for the overseer's countersign per the valve.

## Not silently dropped — the guards that keep firing

Every guard whose extern DOES resolve still runs and a `Value(0)` folds to a HARD
fail. Only the 4 whose twin `.asm` is gated off go inapplicable (NATIVE_DEBUG=1
prints the count).
