## 5. Type-layer design (step-2 item 6 is the type-rich part of this tranche)

`Sst` is fully typed, and this file is almost entirely *raw ROM descriptor bytes
→ typed SST fields*. Decisions taken here, executed at step 1/2:

- Every proc that takes the parent SST takes **`(a0: *Sst)`** (core.emp's
  `DeleteObject (a0: *Sst)` precedent) and `PopulateSpawnedPieceCount` takes
  **`(a2: *Sst)`**; descriptor pointers are `(a1: *u8)` (ROM byte cursors, the
  `Load_Object (a1: *u8)` precedent).
- **`d2` in the four table-driven creators carries a code_addr word read from
  ROM → `ObjRoutine`.** Same for `d0` at `CreateChild_Linked` /
  `CreateEffect_Simple` (documented "objroutine value") and the `d4`/`d2`
  copies they park it in. This is the file's one genuine register-slot newtype
  adoption; the value is MOVED and STORED (never arithmetic), so it types
  cheaply under the strict-degrade lattice.
- `d1` counters, `d3`/`d5` loop counters: raw `u16` — counters are not a domain.
- The spacing bytes (`d2.b`/`d3.b` in `_Linked`) and the descriptor x/y offset
  bytes are **signed PIXEL OFFSETS that become part of a `Coord`** after
  `ext.w/swap/clr.w/add.l`. There is no offset newtype in `types.emp`, and the
  values live in a shift/`ext` chain — exactly the A4-i-gated class. **LEDGER as
  an item-13 candidate (PixelOffset/CoordDelta), do not force.**
- `d1` in `_Linked` holds a **slot pointer as a bare word** (`movea.w d1, a1`),
  relying on RAM living in the sign-extending `$FFFFxxxx` window — same shape as
  the `Sst.parent_ptr`/`sibling_ptr` `u16` fields. Typing it needs a
  `SstPtr16`-class newtype that does not exist; LEDGER with the F2 note, and
  make the sign-extension reliance an explicit contract comment (C2's input).
