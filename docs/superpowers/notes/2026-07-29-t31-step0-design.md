## The SpawnDesc hoist (t30's B1 finding 3 / descriptor census, PRE-RULED)

CreateChild_Normal AND CreateEffect_Normal read the SAME 4-byte record
`{ code: ObjRoutine :w, x_off: i8, y_off: i8 }` (children.emp:108-111 / 542-545),
terminated by a SEPARATE `dc.w 0`. Today the two emitters each define a FUSED 6-byte
`struct EffectSpawn1 (size:6) { code@0, x_off@2, y_off@3, term@4 }`.

- **Add** `pub struct SpawnDesc (size: 4) { code: ObjRoutine @0, x_off: i8 @2, y_off: i8 @3 }`
  to children.emp — the format's owner (the ObjDef-in-sst.emp precedent). Type-only, zero
  bytes; no code change; byte-neutral engine touch.
- **Emitters** drop EffectSpawn1, `use engine.objects.children.{SpawnDesc}` (and drop
  `ObjRoutine` from their `use engine.types` — it was only EffectSpawn1's field type), and
  spell the descriptor as `data X_desc: SpawnDesc = SpawnDesc{…}` + a SEPARATE
  `data X_term: u16 = 0`. 4 + 2 = 6 bytes, byte-identical to EffectSpawn1 → the G2 byte
  gates prove it.
- **test_parent** (the MULTI-entry consumer): `data child_desc: [SpawnDesc; 3] = [ … ]`
  (12 bytes) + `data child_desc_term: u16 = 0` (2 bytes) = 14, matching the AS `.child_desc`.
  This realizes the ruling's "`[SpawnDesc]` + explicit terminator" form directly.
- **Layout proof:** module items emit in SOURCE ORDER (sprites.emp:473 `CellOffsets_XFlip`
  sits BETWEEN Render_Sprites and Emit_ObjectPieces and byte-matches), so `child_desc` +
  `child_desc_term` placed between the TestParent and TestParent_Main procs land at the AS
  `.child_desc` offset. Two consecutive `data` decls are contiguous (u16 after a 4-byte
  struct is already even-aligned).

### Harness note (SpawnDesc visibility)

SpawnDesc is a PURELY `.emp`/sigil-harness concern — the real dual build uses the AS twins
(raw `dc`) and never sees it. The harness `with_ambient` model prepends a dep file's items;

`Item::Struct(d) if d.name == "SpawnDesc"` (type-only, zero bytes). Prepend it to the two
emitters' + test_parent's compiles.
