## 2. Lane A (z80_init) — two walls

### Wall A1 — compound / expression symbolic imm16 does not lower
z80_init's three symbolic-imm16 lines:
```
ld  bc, (Z80_RAM_END-Z80_RAM)-Z80_IdleProgram_CodeEnd-1   ; const − linklabel − 1
ld  de, Z80_IdleProgram_CodeEnd+1                          ; linklabel + 1
ld  hl, Z80_IdleProgram_CodeEnd                            ; bare linklabel  ← the ONLY form T1 wired
```
T1's symbolic path (`lower/code.rs:1715` gate, `lower_z80_abs16_sym:1751`) matches ONLY a
**bare** `CodeOperand::Sym(name)` and builds a `Value16Le` fixup with target `Expr::Sym(name)`.
Any operand that is an EXPRESSION (`Label+1`, `const-Label-1`) is evaluated comptime by the
operand mapper and **errors `unknown name`** before the symbolic path is reached — proven for
`ld de, Target+1` (same-section) AND `ld de, End+1` (End in a separate `(cpu:z80)` section, the
exact pattern that works for a bare `ld hl, End`). So 2 of z80_init's 3 imm16 lines cannot lower.

- **The 68k defer machinery EXISTS**: `move.l #(Target+1), d0` lowers correctly to
  `20 3C 00 00 12 35` (deferred link fixup with an addend). The Z80 immediate operand path
  simply does not route through it — it folds comptime and errors.
- **Brief/T1-note discrepancy #1 (tree wins):** T1 note §1.1 lists `ld de/hl, Label±k` as a
  demanded, handled form, and §4 says the symbolic imm16 is "the one genuinely new fixup wiring
  in T1 ... corpus-demanded by three z80_init lines." The IMPLEMENTATION handles only the bare
  form; the `±k` forms two of those three lines use do not lower. T1 under-delivered vs its own
  note.
- **Fix shape (bounded, and arguably in-envelope since it is fixing T1 to match its note):** the
  Z80 immediate-operand handling must, when the operand is an unresolved-label EXPRESSION, defer
  it to a `Value16Le` fixup carrying the Expr (not fold-and-error) — the analog of the working
  68k `#(Label+1)` path. `lower_z80_abs16_sym` then builds the fixup from the Expr rather than a
  bare `Expr::Sym`. Medium effort; TDD ladder = the z80_init lines as pins.

### Wall A2 — no end-of-code label mechanism
`Z80_IdleProgram_CodeEnd` is a label at the END of the idle code (referenced 3×). A bare
mid-section / end-of-proc label (`CodeEnd:` after a proc inside a section) is a **parse error**
("expected a declaration, found Ident"). The T1 test only ever put its target label as a `data`
decl in a SEPARATE section with a hardcoded `vma:` — which cannot express "the address right
after this code" (the value depends on the encoded length). So z80_init's internal end label
needs a label-expressing mechanism the grammar lacks in this position (`here()`-bind, an
end-of-section label form, or a zero-size data marker — none verified to work).

Lane A therefore needs BOTH A1 and A2. Its oracle, once unblocked, is the game_debug
windowed template applied to a `(cpu:z80, phase 0)` section (canonically empty → an
off-canonical no-sound-shape oracle; the `Z80_IDLE_SIZE` ownership-flip is NOT needed for the
windowed oracle — it is a full-no-sound-build concern, deferrable exactly as the brief §2
DEMAND-3 machinery row anticipates).

## 3. Lane B (seq_opcode_tab) — one wall (a documented T1 deferral)

The 32 cells are `dw <resident-Z80-label>` (`Seq_Op_Vol` … `Seq_Op_End`, `Seq_BadOpcode`) —
RESIDENT phase-0 Z80 code addresses, defined AS-side in `sound_sequencer.asm` (one of the five
resident code files the brief forbids touching), read through the `$8000` window as raw
little-endian data.

- `dc.w Seq_Op_Vol` in a `(cpu:z80)` section → `Cell::SymRef` (`eval/asm.rs:856-857`) →
  `fixup_kind(Cpu::Z80, 2, windowed=false)` → **`[cross-cpu.unwindowed-pointer]`** (the guard at
  `lower/data.rs:169-177`), because the guard assumes any symbolic Z80-section pointer is a
  68k address needing `winptr()`. These are NOT 68k addresses and must NOT be windowed.
- `data [u16;N] = [Seq_Op_Vol, …]` (the array form) → **`unknown name`** (the element evaluator
  folds comptime; the corpus `data` arrays reject bareword link cells — the t26-panel finding).
- The kind these cells need — a resident-Z80-address VALUE cell, little-endian, no masking — is
  **`Value16Le`, which IS the Z80 `Cell::Expr` default** (`lower/data.rs:216`). But nothing in the
  `.emp` surface routes a bareword resident label to a `Cell::Expr`; `dc` produces `SymRef`, the
  array evaluator folds. The code author **explicitly deferred this** (`lower/data.rs:179-185`):
  *"Supporting a genuine Z80-local 16-bit label ref (an `Abs16Le` that does not yet exist) will
  require T6 to SPLIT the `(Z80, _, false)` arm by width, not to route here."*
- **Brief/T1-note discrepancy #2 (tree wins):** T1 note §1.2 and brief §1 lane B state
  seq_opcode_tab "demands NOTHING new … rides the existing `.emp` data path / `Cell::Expr{le:true}`
  / `Value16Le`." The tree shows the resident-label→`Value16Le` routing is unimplemented and
  self-documented as deferred to "T6." (`dac_sample_tab`, comptime consts only, DOES ride the
  path — see §4 — so the "nothing new" claim is true for C, false for B.)
- **Fix shape:** a spelling + lowering that emits a bareword resident-Z80 label as a `Value16Le`
  value cell (the `Abs16Le`/`(Z80,_,false)`-split the comment names). Bounded but a genuine
  design call — it decides how a resident-Z80-address is distinguished from a 68k-address-needing-
  `winptr` at a `dc.w`/data cell. Reversing the author's explicit "defer to T6" is an
  overseer/Fable-owned scope decision, not a porter improvisation.

## 4. Lane C (dac_sample_tab) — data CLEAN; only the seam remains

- The body is `db`/`dw` of build-time `SND_*` constants (bank/rate/codec/ptr/len/loop per
  descriptor). Probed: `data [u8;3]=[SND_BLIP_BANK,0,0]` + `data u16 = SND_BLIP_PTR` … lowers to
  the exact little-endian bytes (`0a 00 00 | 00 81 | 00 02 | 00 00`). **P1 (Z80 LE data) holds
  for comptime-constant cells.**
- The `if (End-Start) <> DAC_SAMPLE_COUNT*DacSample_len / fatal` size guard has a clean comptime
  `.emp` equivalent: `ensure(<total> == DAC_SAMPLE_COUNT * DacSample_len, "…")` — verified to
  lower with BOTH `const` operands AND `extern("DAC_SAMPLE_COUNT")` operands. **P5 (comptime size
  guard) is expressible**; its positive control is doctoring the extern so the `ensure` fires.
  (`sizeof(T)` on a data LABEL does NOT work — "unknown type"; use the declared array length /
  an end-minus-start, not `sizeof`.)
- **Remaining blocker = the banked-head SEAM (shared with B).** dac_sample_tab is CANONICAL, so a
  real port must place the `.emp` section at the phased LMA (`vma:$8000+head_offset`, physical LMA
  after the AS-side head content) and gate the include, so `build.sh` emits the canonical ROM from
  the `.emp`. This is the step-0 seam question the brief flagged. Complications:
  1. The `.emp` section is a phased `vma:$8000` table wedged BETWEEN AS-side content
     (`sound_tables_z80` + pitchtable + sfxtab BEFORE; `dephase/restore` + MT song AFTER) inside
     ONE `phase 08000h` block. The `bank:$8000` / VMA==LMA precedent (`dac_samples.emp`) does NOT
     apply — those are payload banks, not phased head tables.
  2. The named options (brief §2): include-site `ifndef` gate + **org-advance twin arm** (the t23
     boot_data cursor-contract class, kill-row precedent 46) — the AS side `org`s forward past the
     `.emp`-placed span so `dephase/restore`/MT-song land unchanged — VS a chained-section split.
     Either needs a region pin (P4) and exact LMA agreement.
  3. Lane C is CO-LOCATED with lane B in the same phase block (B immediately precedes C). Porting C
     alone while B stays AS couples C's placement to B's still-AS span — an awkward isolated seam.

A windowed oracle (game_debug template: compile `.emp` at `vma:$8000`, assemble the `.asm` twin
via the AS front-end with `SND_*` equs, byte-compare) would prove P1+P5 at the "scale that fits"
WITHOUT the seam — but it does NOT wire the file into `build.sh` (the AS twin stays authoritative)
and does NOT exercise P4 (pins round-trip). So it is a rung-0 PROBE, not a port.

## 5. Recommendation (overseer decision)

The premise that gated this tranche ("T1 done → satellites just port") does not hold: **every lane
needs a sigil capability T1 deferred**, and two of the three deferrals are documented as future
work in T1's note (`ld de,Label±k`) and in `lower/data.rs:184` ("T6 Abs16Le"). Building three
language features + the banked-head phased-placement seam inside one byte-neutral LEAN tranche is
the balloon the rules forbid; and reversing "defer to T6" / T1's operand scope is a Fable-owned
design call, not a porter improvisation. So I STOP at step 0.

Options for the re-scope, cheapest-correct first:

- **(R1) Sigil-only capability step FIRST, then the satellites.** Land the three deferred
  capabilities as a TDD'd, corpus-scoped sigil sub-tranche — (a) Z80 expression-imm16 defer
  (route `ld rr,<expr>` / `jp <expr>` through the existing defer, Expr-targeted `Value16Le`);
  (b) an end-of-code label mechanism for a Z80 code section; (c) the resident-Z80-address
  `Value16Le` value cell (the `(Z80,_,false)`-split). Then z80_init / seq_opcode_tab port
  trivially against them, and dac_sample_tab needs only the seam. Cleanest; matches "demanded
  feature = its own design + build."
- **(R2) Narrow t27 to lane C + the banked-head seam.** Land dac_sample_tab (data + `ensure`
  guard) with the org-advance twin-arm seam + region pin (proves P1, P5, P2-placement, P4), and
  DEFER A and B to R1. Caveat: C is co-located with B in the same phase block, so C's seam must
  account for B staying AS (an org that skips only C's span, leaving B's AS include in place — the
  order is B then C, so C is the tail of the head; tractable but must be designed).
- **(R3) Rung-0 probes only (no ports).** Land windowed oracles proving P1 (Z80 LE data via
  dac_sample_tab's real cells) + P5 (the `ensure` guard, doctored-extern positive control), close
  gap-ledger row ~825-831, and defer ALL three ports to R1. Smallest; no seam, no `build.sh` wiring.

My read: **R1** is the honest sequence (the campaign's own "demanded feature gets its own design +
build" law), with **R3** as the minimal-now fallback if the overseer wants a landed byte this
tranche. R2 is viable but carries the B/C co-location coupling.
