**entity_data — the objentry/objend replacement (macros.asm's last 2 consumers):**
- An **object entry** is a packed 3-word record `[u16;3] = [x, y, flags|(type<<8)|subtype]`
  (the AS `objentry` macro's pack, now baked by the generator) + a `$FFFF` list
  terminator. `pub data OJZ_Sec{N}_Objects: [u16; L]`.
- A **ring list** is `[u16]` X,Y pairs + a longword-0 terminator (two zero words).
- A **type table** is a packed struct `ObjTypeTable{K} { count: u8, pad: u8, t0..t{K-1}: *u8 }`
  — the count byte + pad byte + `K` `dc.l ObjDef_*` pointers. `.emp` packs structs with
  NO padding (layout.rs §"declaration order, no padding"), so the pointer lands at
  offset 2 (even, m68k-legal), matching the AS `dc.b count,0` + `dc.l` byte layout.
  `K = 0` sections use `[u8; 2] = [0, 0]`. The `ObjDef_*` archetypes (test_objects /
  path_swap) are cross-module link labels.

## §2 — Two `.emp` idioms found (recorded)

1. **A same-module data label is not a valid bare identifier in a data initializer.**
   `OJZ_Act_Pool_PageTable: [*u8;3] = [OJZ_Act_Pool_Page0, ...]` fails `unknown name
   OJZ_Act_Pool_Page0` (the labels are defined in the same module, above). It must be
   `extern("OJZ_Act_Pool_Page0")` (resolved at link — the block-blobs dedup-alias
   precedent). CROSS-module bare refs DO resolve (`t0: ObjDef_Solid` in entity_data
   worked). So the rule: **bare = cross-module link label; `extern()` = same-module
   forward/back reference in data.**
2. **The repin `[[region]]` name drives the generated pin CONST name.** Region
   `entity_data` → `pins::ENTITY_DATA` (not `OJZ_ENTITY_DATA`); a mismatched registry
   reference is an E0425 until aligned. Name the region to the intended pin.
