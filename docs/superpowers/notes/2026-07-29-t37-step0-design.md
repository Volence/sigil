## 1. Window derivation — BOTH shapes (measured from s4.lst / s4.debug.lst)

sfx is the **4th include** in z80_sound_driver.asm's `cpu z80 / phase 0` blob (order: sequencer →
**sfx** → fm → psg → tables). Its window sits between the sequencer's end and fm's first label
(Fm_YmWrite). Measured label addresses (extracted from both listings):

| Symbol | plain | debug | Δ | role |
|---|---|---|---|---|
| Sfx_QueueEntryPtr (first sfx byte) | **$0CD7** | **$0D55** | +$7E | sfx window BASE |
| Fm_YmWrite (first fm byte = sfx end) | **$12C3** | **$1341** | +$7E | sfx window END |
| **sfx window length** | **$5EC = 1516 B** | **$5EC = 1516 B** | **0** | SHAPE-INVARIANT length |

**Verdict: sfx is the PSG t32 CASE — shape-VARIANT BASE (+$7E from the sequencer's upstream
`__DEBUG__` growth), shape-INVARIANT LAYOUT (identical 1516-B window length both shapes).** This
is the OPPOSITE of t36's sequencer (shape-invariant base $0565, shape-variant layout +$7E internal),
and matches the brief's prediction ($0CD7 plain / $0D55 debug). The two byte images still DIFFER
(so `plain_and_debug_shapes_differ` holds): (a) the base differs, so every internal `jp`/`call` to
a same-file label carries a different absolute operand, and (b) every external `call`/`jp` to
fm/psg shifts +$7E.

### 1.1 sfx has NO internal `__DEBUG__` / `if DEBUG` blocks (the layout-invariance proof)

`grep -nE '__DEBUG__|if +DEBUG|Seq_Trace'` over sound_sfx.asm → **NONE**. The `if DEBUG == 1`
precedent (t36) is therefore NOT exercised here. sfx's ONLY comptime conditionals are:
- `if SND_SFX_DISP_END > SND_REQ_BASE` (line 88) — a build-time overrun `fatal`, emits nothing.
- `if SFXID_REV_LOOP >= 0` (lines 698-704) — a **GAME-CONFIG** conditional (NOT debug). In the
  sonic4 build `SFXID_REV_LOOP = SFXID_SPINDASH = $AB` (≥ 0), so the block **IS emitted in BOTH
  shapes identically** (game config does not change between plain/debug). The block emits
  `cp $AB` + `ld hl, Snd_SpindashRev` + `ld (hl), 0` — shape-invariant.
- three table-length `if (End - Base) <> COUNT` asserts (1357/1393/1412) — emit nothing.

`>=` is fully supported in the .emp comptime evaluator (Tok::Ge / BinOp::Ge / eval_ordering) — the
`if SFXID_REV_LOOP >= 0 { … }` port needs NO new feature. I will pass a `DEBUG` define to the
oracle for template uniformity, but it changes ZERO sfx bytes.

### 1.2 No own dispatch trampoline

`grep 'ex (sp)'` over sound_sfx.asm → **NONE**. sfx carries NO `ex (sp),hl` dispatch trampoline
of its own; it does not ride the trampoline feature. (The shared interpreter it CALLS —
Sequencer_Channel — uses the trampoline internally, but that lives in the extern sequencer.) So the
brief's "if sfx's dispatch differs in kind, that's a demanded-feature TDD or STOP" branch does NOT
fire: sfx has no in-file dispatch machinery at all — its multi-tier voice selection is plain
compare-and-branch ladders.

## 4. The invariant(ix) adjudication — the t36 MIRROR (confirmed by ledger row 1777)

**Sfx_Frame IS the sfx-side channel walker** (`ld ix, SND_SFX_CHANNELS` … `add ix, de` per slot,
tail-reached from Sequencer_Frame). Ledger row 1777 (t36) EXPLICITLY names `sound_sfx.asm:294` as
the 2nd ix-reliance site: Sfx_Frame reads `(ix+sc_flags)` + `call Sfx_Restore` + `add ix,de` AFTER
`call Sequencer_Channel`, relying on Sequencer_Channel preserving ix (true in fact, checker-invisible
across the computed dispatch). So sfx mirrors the sequencer EXACTLY:
- **NO module `invariant: preserves(ix)`** — Sfx_Frame irreducibly clobbers ix; so do Sfx_DrainQueue
  (tail-jp Sfx_BeginSound), Sfx_DuckRamp, SfxDispatch, Sfx_BeginSound, Sfx_SelectVoice, Sfx_StopAll,
  and Sfx_SlotPtr (out ix).
- **Per-proc `preserves(ix)` on the verifiable leaf set** — the push/pop-bracketed or iy-walking
  procs: Sfx_Steal, Sfx_MusicKeyOffKeepKeyed, Sfx_Restore (all push/pop ix around music-channel
  work), Sfx_MusicChanPtr / Sfx_DeepestDuck / Sfx_MinActiveKind (walk via iy, ix untouched),
  Sfx_RouteKind (clobbers only af), Sfx_QueueEntryPtr, Sfx_QueueEnqueue.
- The Sfx_Frame ix-across-Sequencer_Channel reliance is documented as the checker-invisible mirror
  of t36 §3.4 — NOT forced into a false module invariant. **Adjudicate, don't force** (brief §1).
