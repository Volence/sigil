## 2. The gate structure — player_common is NOT a whole-file gate

player_common.asm is the HARD ROOT: its zero-byte HEADER (the `PlayerV struct`, the
`_pl_*`/`PPHYS_*` equates, `BUTTON_JUMP_MASK`, and the 4 macros) is consumed by the
surviving player_ground/air/spindash. If the whole file gated out, those symbols
vanish AS-side and the AS build breaks. So:

- **player_common.asm → INTERNAL gate.** The header (lines 13-113) stays
  ALWAYS-EMITTED (zero bytes); ONLY the code (`Player_Init`…`Player_DebugMove`) is
  wrapped `ifndef SIGIL_EMP_PLAYER_COMMON … else org $10452 … endif`. main.asm's
  `include player_common.asm` (line 45) is UNCHANGED. This is the row-58 inline-org
  class, INSIDE the file. Deviation from the main.asm-gate pattern, justified by the
  shared-header requirement (the boot/boot_data-split analogue kept in ONE file).
- **sonic.asm → whole-file gate** in main.asm (standard row-60 pattern):
  `ifndef SIGIL_EMP_SONIC / include sonic.asm / else / org $10C66 / endif`. sonic has
  NO surviving-AS consumer of its symbols (PhysTable_Sonic/Sonic_InitAssets/LoadArt
  are read only by player_common, which ports too) → clean whole-file gate.
- **Mixed whole-ROM build sets BOTH gates together** (the tranche's `mixed_tranche34`);
  per-region windowed tests set each gate independently. The cross-file AS reference
  (player_common.asm reads PhysTable_Sonic) is safe because in the mixed build BOTH AS
  files gate out together — no dangling AS symbol. sonic.emp compiles standalone
  (references zero player_common symbols); player_common.emp reads PhysTable_Sonic as a
  cross-seam link symbol when only its own gate is set.

## 4. The macro → comptime-fn templates (macro-port rule; interface redesign)

The census/brief say "3 macros"; the tree has **4** (setStandingSize + setBallSize are a
PAIR the census counts as one). CENSUS CORRECTION flagged.

1. **set_standing_size() / set_ball_size()** — two named fns (closed pair; reads best
   at the PHook call sites), each splicing two `move.b #RADIUS*2+1, {width/height}(a0)`.
   Expanded ONLY by player_common (→ .emp); the AS macros survive in the header but have
   no surviving AS expander. Radii are engine consts (mirrors, §5). Guard upgrade: the
   raw `#N*2+1` immediates fold at comptime from the typed radii.
2. **mask_opposing_lr(held: Reg) -> Code** — the L+R→neither mask with a HYGIENIC
   internal label (emit_piece_loop class; the AS `.lr_masked` fixed label expands once
   per global scope, the comptime-fn splice gives per-expansion hygiene). Expanded by
   player_common (Ground_Move? no — by ground/air only AS-side; player_common itself
   does NOT expand it). **CORRECTION: player_common.asm does NOT expand maskOpposingLR**
   (grep: 3 sites = ground×2, air×1). So this template is a LOCKSTEP twin the .emp
   builds for FUTURE P2/P3 consumers but does not itself call — its home is
   player_common.emp (format-owner), P2/P3 import. Byte-locked to the AS macro.
3. **dist_to_fix(v: Reg) -> Code** — ADOPTS `pixels_to_coord` (kill row 49). CENSUS
   ERROR: the census says "distToFix IS the swap/clr.w pair = pixels_to_coord"; the tree
   distToFix is `ext.l / swap / clr.w` — THREE instructions (the leading `ext.l` the
   census omits). So `dist_to_fix` splices `ext.l {v}` + `pixels_to_coord(v)` (adopting
   row 49 for the promotion half, byte-identical at step 1). The `ext.l` is a step-5
   dead-code CANDIDATE: it sign-extends .w→.l, but `swap`+`clr.w` then discards that
   high word entirely, so it has NO effect on the output — flagged for the C1
   live-question / step-5 (byte-moving; touches surviving player_air's 4 expansions +
   player_common's 1 → wave discipline). Expanded by player_common (Player_SnapToSurface
   ×1) AND surviving player_air (×4) → LOCKSTEP twin, drift-gated by the byte gates.
