## What was built

- **ISA** (`sigil-isa/src/m68k.rs`): `Mnemonic::{Subx, Abcd, Sbcd, Negx, Nbcd}`.
  `encode_x_pair` encodes `addx`/`subx`/`abcd`/`sbcd` as
  `base | Rx<<9 | ss<<6 | rm<<3 | Ry` for `Dy,Dx` (`rm`=0) and `-(Ay),-(Ax)` (`rm`=1);
  `addx` gains its predecrement form. `negx` (`0x4000`) and `nbcd` (`0x4800`, no size
  field) join `encode_single_ea` over data-alterable EAs. The decimal forms are byte only.
  `writes_last_operand`, `family_name` and `ALL_FAMILY_NAMES` classify the five.
- **Decoder** (`m68k_decode.rs`): decodes all six, both forms; the 68020 `pack`/`unpk`
  words on the `sbcd`/`abcd` rows stay named `Unknown`.
- **AS front end** (`eval.rs`): the five spellings; bare `addx`/`subx`/`negx` default to
  `.w`, bare `abcd`/`sbcd`/`nbcd` to `.b` (asl's answers). `lower_m68k_movem` routes a
  `(d16,PC)` or `(d8,PC,Xn)` memory operand through the backend's PC-relative lowering,
  whose sentinel probe locates the displacement after the register-mask word, so the
  base is the EA extension word (address + 4). A PC atom that still reaches the plain
  atom path is a second PC-relative operand, i.e. a destination, and the diagnostic now
  says that instead of "not yet supported".
- **`.emp`**: `flag_check.rs` classifies the new enum variants with the roles its
  by-name arms already gave these words (the match is exhaustive, so this was forced).
  `.emp`'s own mnemonic table is unchanged: no language surface was added (gap ledger).
- `docs/.../2026-09-17-asl-warn-180/sigil_refuses.tsv`: the `s03_sigil_refuses_nbcd`
  row is dropped, because `as_odd_address.rs` requires every listed refusal to still be
  refused. That probe (`nbcd (1).w`) is now compared: asl silent, sigil silent.

Capstone agrees with every encoding except two capstone defects the repo's sweep
already names or now names: (1) for `movem` and `btst #n` it resolves the PC target
from the FIRST extension word, 2 short (the existing `pc-base-after-extension`
exclusion; asl places `T` at `$70` and capstone says `$6e`); (2) it reads
`sbcd -(Ay),-(Ax)` as two words (`sbcd -(a3), -(a5), #$8b0b`), which desynchronises the
sequential decode after it in `x02`. The PRM and asl both make it one word (`8B0B 8B0B`
back to back). That second defect is new here and is now a named exclusion,
`sbcd-predec-length`, with its class size pinned at 64 words.

The whole-opcode-space check is stronger than this table: the decoder now decodes the
six instructions, so `m68k_capstone_differential::opcode_sweep_agrees_with_capstone`
compares every one of their words against Capstone, and `m68k_opcode_sweep` requires
each decoded word to re-encode to its bytes. Before the exclusion was added the sweep
reported exactly 64 disagreements, all `[length]` on `sbcd -(Ay),-(Ax)`; every
`addx`/`subx`/`abcd`/`negx`/`nbcd` word agreed.
