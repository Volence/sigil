## The mechanism — Chained placement computes every resume point

The linker already supports two placements (`sigil_ir::SectionPlacement`): `Pinned`
(base = the section's baked `org`/lma) and `Chained` (base derived at link by packing
after the prior section in its `group`, `relax.rs::place_pass`). Stage 1's native
driver PINS everything: the AS residual at its `org` addresses (incl. the gate
else-arm resume orgs) and each `.emp` at its `pins` base. The resume orgs are all
canonical-sonic4 literals (`engine.inc`/`main.asm`, each with the in-tree NOTE "never
set for other games") — which is why demo/Config-A/B could not build natively
(`2026-07-30-flip-stage1-demo-config-native-blocked.md`).

**The proof (`crates/sigil-cli/tests/native_chained_resume.rs`, 2/2 green):** take the
combined (AS-residual ∪ natively-placed `.emp`) sections, sort the ROM (image-bearing)
sections by address, and re-tag every section that ABUTS its predecessor as `Chained`
into a shared group — base COMPUTED by the linker. To prove the address is genuinely
computed and not read back, ZERO each chained section's baked `lma` AND clear its
baked `vma_base` (so the computed lma is the sole address authority — an arbitrary
resume org would leave a stale VMA). Result, both shapes:

| shape | ROM sections | re-chained | header-neutral diffs over the assembled bar |
|---|---|---|---|
| plain | 66 | 16 | **0** over [0, 0x5DB60) |
| debug | 68 | 17 | **0** over [0, 0x5F65A) |

"Header-neutral" = the checksum `$18E` and ROM-end pointer `$1A4` zeroed — the only
bytes that differ, and exactly the full-file/appendix fields the assembled-bar
comparison already excludes (the golden's are computed by `fixheader` over the
appendix'd file; sigil's `emit_rom` folds its own over the assembled ROM). Every
CONTENT byte ≥ 0x200 is identical.

Confidence checks along the way (all resolved, none a real obstacle):
- A false "MOVED text −0x68" was a measurement artifact: there are **5 sections named
  `text`** (OBJDEFS's real data + 4 empty comptime-default `text` sections), so a
  by-name orig-lma map collided. The emitted content is identical; OBJDEFS's existing
  driver handling (the emp map region + the "exactly one non-empty `text`" guard)
  reproduces correctly under address-order chaining.
- Two object-bank code sections carry `reserved_span < placement_span` (Δ8 / Δ0x10),
  but they are Pinned anchors (object bank `org $10000`), so they do not perturb any
  chain. Noted for the production chainer: advance uses the stored `reserved_span`.

## THE APPROACH SIMPLIFICATION (the reason to checkpoint)

The brief's Stage-1 item 1 assumed retiring the ~30 resume arms means EDITING aeon
(parameterize/compute the else-arm orgs per game×config, keeping asl byte-identical
because the gates-ON arms are dead code for the default build). The proof shows a
cleaner path: **the driver computes the resume points; the aeon literals are simply
IGNORED (chaining overrides them).** So:

1. **No aeon edit is needed to unblock demo/Config native.** The demo/Config AS
   residual carries the SAME sonic4-valued resume orgs (they flow from `engine.inc`),
   but a chaining driver discards those values and computes each layout's resume
   points from ITS OWN `.emp` placement. The demo-config-blocked STOP dissolves.
2. **asl stays byte-identical for free** — zero aeon commits in the companion work
   (the strongest possible form of the constraint).
3. **The aeon resume-org literals die at THE FLIP COMMIT anyway** (not mine): brief
   §1 already deletes the gate wrappers/includes/org arms with the twins. Pre-flip
   they are harmless inert break-markers; the driver's computation is what matters.

What the driver-side chainer still owes (the real, bounded work):
- Make the chainer a first-class capability in `native.rs` (generalize the proof's
  address-order re-tag into `build_native_rom`'s placement path, or a sibling the
  demo/Config drivers call), preserving the OBJDEFS `text` guard and the drift-guard
  allowlist partition.
- The `$20000` object-bank budget as a map-region check (brief item 3) is the ONE
  piece that still wants the AS-residual section-split (S1.2-map-growth-finding): the
  object-bank code + level-data are one contiguous AS section crossing `$20000`, and
  a map region validates only whole-section containment. This is INDEPENDENT of the
  resume-org computation (which is now proven) and can be sequenced after the six
  proofs, or folded into the flip when the twins collapse the residual to islands.
