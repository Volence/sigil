### 1.3 THE MODULE-INVARIANT QUESTION — driver is PER-PROC, like the sequencer, NOT psg/fm

- **NO `invariant: preserves(ix)`.** The driver CLOBBERS ix in `SndDrv_Sample` (ix = ROM
  window ptr), `SndDrv_TimerATick` (reloads ix), `Snd_LoadSong` (ix = SeqChannel ptr in
  `.chan_init`), `SndDrv_IdleTick` (transitive via the frame), and `SndDrv_ISR`
  (transitive, un-saved). A module invariant would (correctly) fire on all of them. So ix
  is `preserves`-declared PER-PROC only where true (StartSample push/pop; SetBank /
  RouteClassFlags / the 4 command procs never touch it). This EXACTLY mirrors
  `sound_sequencer.emp`'s explicit "NO module-scope invariant: preserves(ix)" ruling
  (its Sequencer_Frame reloads ix too). Report it as the driver's shape.
- **de = $4001 stays C3 PROSE, NOT a register invariant.** This is the rung-2 §9-A
  discrepancy's named RUNG-4 OWNER, and the ruling holds here: many driver procs CLOBBER
  de (PollMailbox, LoadSong, DacLookup) and de=$4001 is RE-ESTABLISHED at scattered points
  (Init; every tick/idle/startsample reloads `ld de, SND_Z80_YM_A1`). Re-establishment is
  too scattered for a clean module-register invariant; the value-binding form
  (`invariant: holds(de==$4001)`, rung-2 §3.4 — represented, not wired) is NOT demanded
  checkably. It belongs in the module header's hardware-contract block (C3's audit
  surface).
- **reg $2A parked stays C3 PROSE / the `[fm.dac-repark]`-family discipline** (rung-2 §9-B,
  ruling 3 — design-only). The driver re-parks $2A at init/tick/idle/stop/startsample/
  loadsong/timerA. A YM address-port latch is not a Z80 register; no register-contract
  class expresses it.

**Net: the driver demands NO new module-invariant instance.** It is per-proc contracts +
C3 prose for the de/$2A/di disciplines — the sequencer's shape, not psg/fm's.

## 3. THE T-STATE CAPABILITY DESIGN (rung 4 owns Z80 cycle costs; C1's first activation)

Ruled scope (recon §4.3 ruling 2): **straight-line + single-path accounting ONLY**;
whole-CFG cycle bounds are OUT (research project, do not promise). The design is driven
ONLY by the driver's own claims (§1.6) — no speculative generality (adoption-over-
cleverness).

### 3(a) The annotation / contract surface — THREE primitives, each demanded

The driver's claim vocabulary is exactly: a per-PATH T-state count, an EQUALITY between
paths, and a pad DERIVED to hit a target. So:

1. **`cycles(<span>)`** — a comptime fn returning the T-state cost of a STRAIGHT-LINE span
   (a start label to an end point with no interior incoming edges). It sums per-instruction
   T-states from the table (3(b)). A span is named by its bounding labels, e.g.
   `cycles(.loop, .exhaust)` for the FILL trace. Because the driver made every hot branch
   `jp cc` (constant 10), a span's cost is a plain SUM — no branch min/max, no
   outcome dependence. **This is the honest fit to the ruled "single-path" scope: the
   driver engineered branch-outcome-independence, so single-path accounting is EXACT, not
   an approximation.**
2. **`ensure(cycles(A) == cycles(B))` / `ensure(cycles(A) == 195)`** — the path-equality
   and path-target asserts. These ARE the cycle-balance proof, now a checked comptime fact
   (self-gates to zero emitted bytes). The header's "FILL == DRAIN = 195, DRAINING = 194"
   becomes three `ensure`s.
3. **`pad_cycles(N)` / `pad_to_cycles(target, cycles(prefix))`** — a comptime construct
   emitting exactly the `nop`s to consume N T-states (or `target − measured-prefix`,
   DERIVED not hand-counted). The `rept 19/nop` and `rept 21/nop` become
   `pad_to_cycles(FILL_CYC, …)` — the pad tracks the prefix automatically, so a future
   edit to the drain prefix re-derives the pad instead of silently unbalancing the clock.

NOT built (no demand): a `cycles { }` BLOCK form beyond the span fn; min/max branch
intervals; per-op operand-timing variants beyond the table subset; a whole-loop bound.

### 3(b) The checker — T-state table (driver's timed-region op subset ONLY) + path accounting

The timed regions are the three hot-loop paths (FILL / DRAIN / DRAINING_TAIL). Their op
subset (nominal Zilog T-states):

| form | T | in |
|---|---|---|
| `ld r, r'` (`ld l,c`, `ld a,h`, `ld a,b`, `ld l,b`) | 4 | all |
| `ld r, (hl)` (`ld a,(hl)`) | 7 | consumer |
| `ld (de), a` | 7 | consumer |
| `ld (hl), a` | 7 | FILL |
| `ld a, (nn)` (poll/phase/DMA reads) | 13 | prefix |
| `ld a, (ix+d)` | 19 | FILL (the ROM read) |
| `inc r` (`inc c`, `inc b`) | 4 | consumer/FILL |
| `inc ix` | 10 | FILL |
| `dec hl` | 6 | shadow len-- |
| `and n` / `cp n` / `or r` / `sub r` / `or a` | 4–7 | prefix / draining |
| `exx` | 4 | shadow |
| `nop` | 4 | pads |
| `jp nn` | 10 | exit |
| `jp cc, nn` (taken OR not) | 10 | prefix/exit |

Conditional `jp cc` carries ONE cost (10) — taken == not-taken — so no variant is needed,
which is exactly why the driver uses `jp`. `jr cc` (12/7) and `djnz` (13/8) have DIFFERING
taken/not-taken costs; they carry BOTH variants in the table, and **the checker LOUD-BAILS
if a `jr cc`/`djnz` appears inside a `cycles()` span** — the cost is ambiguous, so it
cannot assign one (`[cycles.ambiguous-branch]`). This turns the prose "`jp` never `jr` on
the hot path" discipline into a COMPILE ERROR — the footgun-fixed-not-documented win. (djnz
is not in any timed region anyway — it lives in the init/prime loops, off the hot path.)

**Loud bail for any op/form NOT in the table** inside a `cycles()` span →
`[cycles.unknown-op]` naming the op. The table is the driver-demand subset only; a future
timed region adds its ops explicitly (never a silent default cost). Path accounting is a
straight-line SUM over the span (the constant-`jp cc` property removes all branch
analysis).

### 3(c) The failing-first test plan (non-vacuity per t24)

- **Drift-by-one fires:** doctor the DRAIN pad from `rept 19` to `rept 20` (one extra
  nop, +4 → `cycles(.drain) = 199`). `ensure(cycles(.drain) == cycles(.fill))` MUST fire
  (199 ≠ 195). Positive control (t24): the UNDOCTORED loop asserts `cycles(.fill) == 195`
  AND `cycles(.drain) == 195` and PASSES. Verify BOTH ways.
- **Ambiguous-branch bail fires:** a synthetic `cycles()` span containing `jr z, X` →
  `[cycles.ambiguous-branch]`; the same span with `jp z, X` compiles clean (positive
  control).
- **Unknown-op bail fires:** a span with an op outside the table → `[cycles.unknown-op]`;
  the same span with a table op compiles.
- **The true DAC loop verifies:** with the three real `ensure`s present, the unmodified
  `z80_sound_driver.emp` compiles green AND byte-identical to the AS twin (the cycle
  asserts self-gate to zero bytes, so they cannot move the window).

### 3(d) What rung 4 does NOT model — EXPLICIT exclusions (stay C3 prose)

- **Cartridge-bus contention** / the ~3.3-cyc banked-$8000-ROM penalty on FILL's
  `ld a,(ix+0)` — silicon-only, header says "noted, not padded"; the table counts the
  nominal 19.
- **Interrupt latency / IRQ acceptance** — the RST-38h dispatch cost and the whole
  "/INT-miss in the long di window" argument are real-time /INT-edge timing, not
  statically knowable. C3 prose.
- **68k bus arbitration** during Z80 ROM reads through the $8000 window (the banked-code
  hazard) — C3 prose, unchanged.
- **The Timer-A tick's cost** (`SndDrv_TimerATick`: spill/frame/refill/reload) — the
  once-per-frame off-hot-path work, NOT cycle-balanced (the DAC holds its last sample =
  a wall-clock effect, not a rate effect). Not a timed span.
- **Whole-CFG / wall-clock bounds** — ruled out (research project).

## 4. THE di/ei + SHADOW-SET CONTRACT STORY (designed from real usage)

### 4.1 di/ei — NO new contract surface; stays C3 prose (argued both ways)

**Recommendation: di/ei get no contract-clause vocabulary at rung 4.** Argument:

- **FOR a checker** (rejected): an IFF-state lattice (di-held / enabled / unknown per
  program point) could lint "every `di` is balanced by an `ei`" or "the streaming body
  runs interrupts-off."
- **AGAINST (the ruling):** the LOAD-BEARING property the driver relies on is "the
  once-per-frame /INT never lands in the multi-thousand-T-state di window, so the ISR does
  not fire during streaming" — a TEMPORAL /INT-edge argument the assembler cannot evaluate
  (whether an interrupt lands depends on real-time hardware edges). An IFF-balance lint
  would check the TRIVIAL half (di/ei pairing) while giving false confidence about the
  UNMODELABLE half (the timing). That is speculative generality that checks the wrong
  thing — the exact adoption-over-cleverness trap. The di/ei reasoning is a
  hardware-timing CLAIM, which is precisely the C3 lens's job (codified panel-activation
  rule: C3 activates on ported hardware prose; the t33 precedent caught a stale DAC-loop
  timing claim). So di/ei live in the module header's hardware-contract block, audited by
  C3, NOT a new contract class.

(This confirms the rung-2 §4.4 deferral's resolution: di/ei were "named for rung 4"; the
rung-4 answer is "prose, not a lattice.")

### 4.2 Shadow set — WIRE the already-designed rung-2 §4.3 balanced-`exx` recognition; no new vocabulary

> **CORRECTION (t40 step 1, 2026-07-29 — overseer ruling 3 OVERTURNED, defer confirmed):**
> the "WIRE it now / demanded by this file's honest contracts" premise below is FALSE.
> The driver has NO returning proc that crosses an `exx` pair with a declared preserve
> (both exx procs are non-returning loop entries; no module invariant), so the
> conservative `exx`-clobbers-bc/de/hl treatment blocks nothing and the recognition is
> UNEXERCISED. It is DEFERRED to a file that actually declares a preserve across an exx
> pair (gap-ledger row [t40 step-1]; the `ex af,af'` represented-not-wired precedent).
> The text below stands as the original (wrong-premise) design; read it with this pointer.

The driver's shadow usage (§1.5) is: `hl'` as a LOOP-CARRIED live register (ROM len),
accessed only inside BALANCED `exx … exx` pairs; no `ex af,af'`; no proc ever DECLARES a
`preserves(hl')` (hl' is internal loop state, never a cross-boundary preserve). So:

- **The one checker mechanism to WIRE** is rung-2 §4.3's balanced-`exx`-pair recognition
  (represented there, not yet wired — no rung-2/3 demand): `exx` swaps the entry-value
  bits `{bc,de,hl} ↔ {bc',de',hl'}`; a BALANCED `exx … exx` is a no-op to the main bank
  (bits swap back), so main `bc`/`de`/`hl` entry values survive the pair. This lets the
  z80_preserves sibling correctly credit `preserves(bc,de)` across the FILL/refill shadow
  pairs (which is real: the DAC write's `de=$4001` and the ring `bc` survive every pair).
- **No `ex af,af'` support needed** — unused; stays represented-not-wired (rung-2 §2.4/§4.3).
- **No shadow-register contract-clause vocabulary demanded** — no `preserves(hl')` / no
  `shadow(…)` sub-clause appears. hl' is loop-internal; every CALL that crosses it
  (`SndDrv_TimerATick`'s Run_SeqFrame/PollMailbox) is preceded by an `exx`-spill of hl' to
  `SND_ROM_LEN` and followed by a reload, so the conservative "call clobbers all incl.
  shadow" model (rung-2) is correct and sufficient — no shadow value crosses a call live.

**Net for §4: neither di/ei nor the shadow set demands new CONTRACT-CLAUSE surface.** di/ei
= C3 prose. Shadow = wire the pre-designed rung-2 §4.3 balanced-`exx` no-op recognition (a
checker mechanism, ~one arm on the sibling), plus the loud `ex (sp),hl`/lone-`exx` bail
already represented. This is the minimal, demand-driven answer.
