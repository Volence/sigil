### M.2 Config plumbing (how the off-canonical flags reach both sides)

The campaign's whole-ROM byte gate assembles main.asm through **sigil's own AS front-end**
(`assemble_root`, byte-identical to asl per M0/M1) — NOT a build.sh shell-out. So the config
is a `defines` vector, exactly as `vblank_port::as_full_module` already does it
(`SOUND_DBG_MIRROR`/`SOUND_DRIVER_ENABLED`/`__DEBUG__` as `-D` pairs). Lane M adds
`SOUND_DEBUG_HOTKEYS` and the `SIGIL_EMP_*` gate defines to the same vector. No new
config-plumbing primitive is needed — the mechanism is `assemble_root(main.asm, defines)`.

### M.3 The reference question (a design refinement of the brief — OPEN for the overseer)

The EXISTING whole-ROM mixed gates (`mixed_dac_rom.rs`) compare the mixed build against the
**real asl ROM FILE** (`aeon/s4.bin` / `s4.debug.bin`) — which carries the convsym `deb2`
append, hence `assert_rom_matches_convsym` derives the checksum/ROM-end header allowlist.

**Config A/B have NO pre-built asl reference file** (build.sh never ships those shapes). Two
options:
- **(a) PROPOSED — the pure-`assemble_root` reference.** Reference =
  `assemble_root(main.asm, ConfigX-defines, NO SIGIL_EMP gate)` → the whole off-canonical ROM
  through sigil's AS front-end. Mixed = `assemble_root(main.asm, ConfigX + SIGIL_EMP_* gates)`
  → AS side with the region(s) org-skipped, concatenated with the placed `.emp` section(s),
  one joint `resolve_layout`+`link`. **Both sides are pre-convsym**, so their headers MATCH:
  compare with **`assert_rom_matches` (EMPTY allowlist)**, NOT `assert_rom_matches_convsym`
  (whose "did the reference lose its deb2 append?" guard would FALSE-FAIL on two pre-append
  ROMs). This is self-contained (no external process, no reference file), matches how
  `vblank_mirror_shape_twin_parity` and `game_debug_port` already build their own AS reference,
  and is the natural whole-ROM lift of those window oracles.
- (b) build.sh shell-out to produce a real asl off-canonical ROM (with convsym) →
  `assert_rom_matches_convsym`. Heavier (external toolchain per run, a new cached artifact);
  exercises the real convsym path but that path is already covered by the canonical gates.

**Brief-refinement flag:** the brief names "the `assert_rom_matches_convsym` family" as the
precedent. Under (a) the FAMILY (`assert_rom_matches` machinery) is reused but the
convsym-specific variant is the WRONG member for a two-`assemble_root` comparison — the empty
allowlist member is correct. **OPEN QUESTION 1:** overseer confirms (a) pure-`assemble_root`
reference + `assert_rom_matches`, vs (b) build.sh asl reference + `assert_rom_matches_convsym`.

### M.6 Which window oracles are superseded vs kept (OPEN QUESTION 2)

The three window oracles (`z80_init_port`, `game_debug_port`, and vblank's
`vblank_mirror_shape_twin_parity`) prove the `.emp` region == its `.asm` twin at a **synthetic
base** with hand-fed cross-seam equs. The lane-M whole-ROM gate proves the `.emp` placed in the
**real ROM** at the off-canonical config == pure-asl at that config — it SUBSUMES the region
byte-match AND adds real placement + real cross-seam resolution.

**PROPOSED ruling:** **KEEP the window oracles, ADD the whole-ROM gates.** Rationale: the window
oracles carry the cheap, isolated NEGATIVE/POSITIVE controls (doctored-twin-diverges,
undoctored-equals) that a whole-ROM gate cannot express economically, and they run without a
full-ROM assemble (fast region isolation). The whole-ROM gate becomes the PRIMARY byte-proof;
the window oracles demote to region-isolation + control-liveness. LEAN cost: the window oracles
already exist and are green — keeping them is zero new work; superseding (deleting) them would
LOSE the doctored-diverge controls. **OPEN QUESTION 2:** overseer rules keep-both vs
supersede-window. (My lean: keep both — the whole-ROM gate is additive proof, not a replacement
for the controls.)
