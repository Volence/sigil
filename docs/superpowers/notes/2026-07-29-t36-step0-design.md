Sequencer is include-nesting level `(4)` inside the resident Z80 phase-0 blob
(driver → … → sound_sequencer.asm), immediately BEFORE sound_sfx.asm ("Phase 5a
SFX engine"). Addresses are ABSOLUTE Z80 (the `.coord` caller proves it: `call
Sequencer_Frame` encodes `CD 65 05` = call $0565 in BOTH s4.lst and
s4.debug.lst).

| Bound | Plain (s4.lst) | Debug (s4.debug.lst) | Evidence |
|---|---|---|---|
| Start `Sequencer_Frame` | **$0565** | **$0565** | label line + caller `CD 65 05` both shapes |
| `Seq_Trace` (debug-only body) | $0C3C | $0C94 | +$58 accumulated by then |
| Last label `Seq_FmKeyoffChsels` | $0CD1 | $0D4F | label emission |
| End (after the 6-byte `db`) | **$0CD7** | **$0D55** | next line = sfx file @ same addr |
| **Window size** | **$0772 = 1906 B** | **$07F0 = 2032 B** | end − start |
| **Debug − plain delta** | — | **+$7E = 126 B** | internal `__DEBUG__` growth |

**KEY FINDING — the sequencer is the FIRST resident Z80 CODE file with
INTERNAL `__DEBUG__` divergence.** Start is shape-INVARIANT ($0565 both), but
the WINDOW CONTENT is shape-variant: the debug shape carries **16 `ifdef
__DEBUG__` blocks** — the `Seq_Trace` body (:1920) + **15 scattered `call
Seq_Trace` sites** inside handlers (`.note`/`.rest`/Vol/Patch/Dac/NoteDur/
NoteRaw/PitchEnv/Pan/RepeatStart/RepeatEnd/LoopPoint/Jump/End/BadOpcode) — for
+$7E total.

Contrast the drivers: psg's own layout was shape-INVARIANT (its base
shift was purely UPSTREAM `__DEBUG__` growth); fm was even more invariant.
**This +$7E internal growth is PRECISELY the source of psg's observed
$1660→$16DE (+$7E) base shift** that t32 attributed to "upstream `__DEBUG__`
growth" — porting the sequencer, we now OWN that growth. (psg sits AFTER the
sequencer in the blob, so the sequencer's debug-only bytes push it later.)

**Oracle implication (step 1, not this gate):** like psg/fm, BOTH shapes are
byte-gated separately. UNLIKE psg/fm, the `.emp` body itself must carry `if
DEBUG == 1 { … }` blocks — the FIRST time the 68k-corpus `if DEBUG == 1` idiom
(rings/core) appears in a Z80 `.emp`. The twin's per-shape spans that the trace
sites straddle are the SHAPE-DIVERGENT-relaxation class (step-2 item 1): the
`.emp` stays one source; the AS twin carries the `ifdef __DEBUG__` gate.

## 4. THE DEMANDED FEATURE — the `ex (sp),hl` trampoline (STOP-1)

### 4.1 The site (Sequencer_NextOpcode.coord, :1073–1089)

```
.coord:
        sub  MEV_VOL          ; a = 0..31 (index into SeqOpcodeTable)
        ld   c,a
        ld   b,0
        push hl               ; save stream ptr across the table math
        ld   hl,SeqOpcodeTable
        add  hl,bc
        add  hl,bc            ; +index*2 (dw entries)
        ld   a,(hl)
        inc  hl
        ld   h,(hl)
        ld   l,a              ; hl = handler address
        ex   (sp),hl          ; (sp) = handler, hl = stream ptr restored
        ret                   ; "jp (handler)" leaving hl = stream ptr
```

Stack effect relative to Sequencer_Channel's entry (which is `call`ed from
Sequencer_Frame :98 — the return address sits on top at entry, Sequencer_Channel
falls into Sequencer_NextOpcode :1007):

1. `push hl` → stack `[hl_old, retaddr]`.
2. `ex (sp),hl` → stack `[handler, retaddr]`, register `hl = hl_old` (stream ptr).
3. `ret` → pops `handler` into PC → **computed jump to the handler**, stack
   `[retaddr]`, hl = stream ptr.

The handler INHERITS Sequencer_NextOpcode's return address. The 32 dispatch
targets (SeqOpcodeTable, `engine/sound/seq_opcode_tab.asm`, 32 dw $E0..$FF; ~23
distinct `Seq_Op_*` + `Seq_BadOpcode` on 6 reserved slots) are effectively
TAIL-CALLED CONTINUATIONS, in two exit classes:

- **ZERO-TICK** (Vol/Patch/Dac/Pan/PsgEnv/ModSet/Tempo/Porta/Detune/Lfo/
  PsgNoise/OpBias/RegDelta/RegWrite/Macro/SpinRev/RepeatStart/RepeatEnd/
  LoopPoint/Jump): end `jp`/`jr Seq_ContinueFetch` → `jp
  Sequencer_NextOpcode.fetch` → **loop** (never returns to Sequencer_Frame).
- **TIME-ADVANCING / END** (Seq_Op_NoteDur/NoteRaw/PitchEnv/End, plus inline
  `.note`/`.rest` which are NOT dispatch targets): commit `sc_stream_ptr`, then
  `ret` → **returns to Sequencer_Frame** via the inherited return address.
- **JOIN:** Seq_Op_End is both a dispatch target AND a `jp` target
  (Seq_Op_Jump :1764 `jp Seq_Op_End` for an expiring continuous SFX).

### 4.3 Two demanded sub-features — the design

**Demand 1 — the operand form.** `ex (sp),hl` currently lowers `(sp)` to a bare
`Z80Pair::Sp` (which reaches the encoder's `Operand::Pair(Sp)` arm → $E3), so
byte-emission already works. What is MISSING is a REPRESENTATION the preserve
model can pattern-match: today `sp_hazard` looks for `Z80IndHl`, which
`ex (sp),hl` does not carry. **Design decision (name it):** introduce a distinct
`CodeOperand::Z80IndSp` for the indirect `(sp)` — parallel to `Z80IndHl` — so
`(sp)` is modeled as an indirect (its true semantics), NOT a bare `Sp` pair; the
encoder maps `Z80IndSp` to the same `$E3` arm (byte-neutral), and `sp_hazard`
matches `mnem=="ex" && ops has Z80IndSp` → returns TRUE. (Alternative, cheaper:
match `ex` with a `Z80Pair::Sp` operand in `sp_hazard`. REJECTED — it conflates
`(sp)` with a bare `sp` pair and reads wrong; the doc already calls for a
distinct operand, and `Z80IndSp` also future-proofs `ex (sp),ix`.)

**Demand 2 — ret-as-computed-dispatch semantics (the LIFO/exit model).** The
`ret` at :1086 is NOT a proc exit — it is a computed tail-dispatch. Modeled
NAIVELY (push hl expects a matching pop hl; ex treated as an ordinary op), the
pair-slot proof gives an UNSOUND verdict on TRUE code: the `push hl` at :1077
has no `pop hl`, and the `ex (sp),hl` swap of hl↔(sp) is unmodeled, so hl is
either falsely "preserved" (it was swapped) or the dangling push mis-balances
the stack. **That mis-verdict is the feature spec, not a bug to suppress**
(brief §2). THE FIX: route the recognized `ex (sp),hl` to the existing LOUD
BAIL (the `sp_hazard`→bail path — the same `Edge::Abandon`/bail machinery psg's
tail-jp gap-3 closure built). Semantics of the bail here:

- The trampoline is an EXIT of Sequencer_Channel/NextOpcode's linear CFG; the
  analysis conservatively ABANDONS the path there (`bailed_reached_return`).
- Registers ever-clobbered BEFORE the bail are conservatively reported
  not-preserved (safe direction); `ix`, untouched through `.coord`, stays
  preserved → the module `invariant(ix)` survives, matching Sequencer_Channel's
  honest header (`Clobbers af,bc,de,hl; ix preserved`).
- The 32 handlers are analyzed as INDEPENDENT procs (own labels + own
  contracts), reached via the dispatch — they are NOT walked through the
  trampoline. Each handler's own `preserves(ix)` is verified in isolation.

**The bless / spelling (bless-on-the-producer).** The value-PRODUCING
instruction of the dispatch target is `ex (sp),hl` (it places the handler on the
stack for `ret` to consume), so the bless RE-HOMES there. Recommendation for
endorsement: the `ex (sp),hl` site carries an explicit target-class bless that
BOTH (a) names the dispatch's target class for the cold reader (auditability —
the bless-on-the-producer rule wants the dispatch site to NAME its target
class), and (b) makes the bail intentional rather than an incidental
`sp_hazard` side effect. Candidate spellings for the overseer to pick:

- **(A) implicit** — bare `ex (sp),hl` auto-bails via `sp_hazard`; a forced-
  spelling site comment `// [dispatch.trampoline: SeqOpcodeTable]` names the
  target class (greppable, dies with the idiom). Minimal; no grammar.
- **(B) explicit bless** — `ex (sp),hl as dispatch(SeqOpcodeTable)` on the
  producer: routes to bail AND (optionally, later) lets the checker verify the
  32 table entries are real handler labels. More faithful to bless-on-the-
  producer; a small grammar addition.

Recommend **(A) for this tranche** (byte-neutral, zero grammar, the comment
satisfies "name the target class") with **(B) ledgered** as the typed-dispatch
grammar ask — matching the macro-port taste gate (typed-interface only where it
earns adoption; the dispatch has exactly one site). Overseer to endorse the
spelling before wiring.

### 4.4 Failing-first test plan (demanded-feature TDD, t27/t32 class)

1. **Non-recognition proof (the current unsound state):** a fixture proc `push
   hl / <table math> / ex (sp),hl / ret` declared `preserves(hl)`. With
   `sp_hazard` returning false (today), the proof MISVERDICTS — it must be shown
   to either false-PASS the `preserves(hl)` (hl was swapped) or mis-balance the
   dangling push. This is the "LIFO proof fails on true code" demonstration; it
   is the RED test.
2. **Recognition + bail (GREEN):** with `Z80IndSp` + `sp_hazard` matching
   `ex (sp),hl`, the same fixture routes to the loud bail; `preserves(hl)` is
   correctly REFUTED (conservative), `preserves(ix)` (ix untouched pre-bail) is
   VERIFIED. Non-vacuity the t24 way: an injected `preserves(hl)` on the real
   Sequencer_Channel FIRES; the honest `clobbers(af,bc,de,hl) preserves(ix)`
   PASSES.
3. **Byte-identity BOTH shapes:** the windowed oracle (`sound_sequencer_port`)
   byte-gates the plain window ($0565–$0CD7, 1906 B) and the debug window
   ($0565–$0D55, 2032 B) against the extracted ROM; the trampoline emits
   `E3 C9` identically. The `.emp`'s `if DEBUG == 1` blocks + the twin's
   `ifdef __DEBUG__` gate produce the +$7E debug delta exactly.
4. **Positive control (t24 rule, mandatory):** an executable
   `*_undoctored_compile_equals_the_reference_window` proving the undoctored
   trampoline window == the ROM window; a doctored variant (e.g. `add hl,bc`
   dropped so the index math is wrong) MUST diverge. Fixtures PINS-derived so a
   re-pin can't re-stale them.
5. **`ex (sp),hl` encoding regression:** already covered by
   `encode_base16_control.rs` / the golden vector — assert it stays $E3.

## 5. Corrections to the brief (tree wins)

- **(a) Window shape-variance is INTERNAL, not a base shift.** The brief (§1)
  says "psg/fm precedent says shape-variant bases, layout-invariant; VERIFY."
  Verified FALSE for the sequencer: the base is shape-INVARIANT ($0565 both),
  but the sequencer's OWN layout is shape-VARIANT (+$7E from 16 internal
  `__DEBUG__` blocks). It is the FIRST resident Z80 code file whose `.emp` needs
  `if DEBUG == 1` bodies. (This +$7E is the very growth that shifted psg's base
  in t32.)

  `ex (sp),hl` instruction form as possibly-missing ("if the wired set lacks
  it"); in fact the ISA encoder ($E3) AND the AS-frontend parse are already
  done. The ONLY missing piece is the preserve-model representation (a distinct
  `Z80IndSp` operand + the `sp_hazard` match), which the module is explicitly
  pre-wired to receive. Scope is smaller than "a new instruction + a new exit
  model" — it is "one operand variant + flip one `return false` to a match."
- **(c) Census `Out`-count is 2 PROCS across 4 comment lines** (Porta_Apply +
  Mod_Advance, each a 2-line `Out: CARRY`), matching the §5.1 "2 Out-hdrs"
  exactly; the 4-line raw grep is not 4 procs.
