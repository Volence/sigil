## 4 · What the static evidence already establishes

- **The chain is arithmetically equivalent.** `x·80 = ((x·4)+x)·16`, and every
  emitted op is `.w`, i.e. an operation of the mod-2^16 ring, so an overflowing
  intermediate cannot corrupt the low word for any x. The generator's own
  equivalence oracle executes the chosen lowering through an ISA-faithful
  interpreter written independently of the chain constructor.
- **The scratch is dead.** `d2` is declared clobbered by
  `Collision_GetType (…) clobbers(d1-d3/a0) out(d0)` and is never read between
  the multiply and either `rts`: the remaining instructions are `add.w d0,d1`,
  `tst.b d3`, `beq .plane_selected`, `addi.w #TILE_CACHE_COLL_SIZE,d1`,
  `lea Tile_Cache_Collision,a0`, `move.b (a0,d1.w),d0`, `rts`. The only label in
  that span, `.plane_selected`, is reached solely from the `beq` inside it. The
  old chain destroyed d2 as well, so liveness is *unchanged* — only the residual
  value differs (`x` where it used to be `x << 4`).
- **The condition codes are not observable.** The chain's last op changed from
  `add.w d2,d1` to `lsl.w #4,d1`, and the very next instruction (`add.w d0,d1`)
  is itself a flag setter, so no branch reads the moved flags.
- **The upper word is contract-free.** `mul_const.w` is the word form; the
  result is consumed as `(a0,d1.w)`, a word index.

# 6 · The live half — overseer's foreground run (2026-08-06)

Run at merged master (sigil `f4d87aae` / aeon `077dc7d`) on the **plain shape**,
the shipping artifact. `Collision_GetType` sits at `0x5250`; the five changed

## 6.1 · Method

Both carts verified BY HASH, never by the reload diagnostic — which is the
point: the diagnostic's `first16` is byte-identical for the two ROMs, so it
cannot distinguish them. `memory_hash addr=0 len=411167` returned `3B6CAD91`
(OLD, chain 49) and `4F43C8D9` (NEW, chain 50).

The A/B is **frame-locked**, not `pause`-anchored: a `pause` lands at an
arbitrary intra-frame instant whose phase differs between the ROMs *because*
the timing changed. Each run was paused, anchored at `VInt_Level` (`0x20F2`),
then advanced with neutral input (`mode`, verified inert: position and velocity
unchanged, Frame_Counter +1 per frame) until `Frame_Counter == 0x0C00`. All
subsequent stepping is whole frames from that lock.

**The stimulus exercises the collision sensors, which is the whole point** — the
chain-49 A/B used a frozen scene, a camera sweep and an object-churn soak, and
*none of those run `Collision_GetType`*. Four phases, 300 frames:

| phase | input | frames | what it exercises |
|---|---|---|---|
| 1 | `right` | 120 | ground sensors while running; ends pushing against geometry (wall sensors) |
| 2 | `right`+`a` | 20 | airborne, rolling — air/ceiling probes |
| 3 | `right` | 100 | landing and running at speed over varied terrain; camera scroll, cache fills |
| 4 | `down` | 60 | rolling |

## 6.3 · The framebuffer difference is raster phase, and that is a proof, not a guess

The framebuffer is a pure function of (VDP memory, raster position). At A2 and
A3 **every VDP memory region is bit-identical** — VRAM, CRAM, VSRAM and the
register file — so the only remaining free variable is where the beam sits when
the frame was captured. A cycle-changing parcel moves exactly that. There is no
third input that could differ.

The evidence agrees with the construction: the framebuffer **reconverged to
bit-identical at A4** while work RAM stayed identical at every anchor
throughout. Content divergence compounds; it does not spontaneously return to a
bit-identical frame.

## 6.4 · An attempted extra check that FAILED, recorded rather than dressed up

To pin the phase claim independently I replayed both ROMs to A2 and re-captured

artifact of that mismatch, not a finding. The experiment is **discarded as
inconclusive**; it is recorded here so nobody re-derives it and reads the
artifact as a defect. The frame-stepped comparison in 6.2 is the sound one.
