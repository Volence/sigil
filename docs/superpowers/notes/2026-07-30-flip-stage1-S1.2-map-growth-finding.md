# 2026-07-30 — FLIP STAGE 1 · S1.2 map-manifest growth — the placer-granularity finding

Status: **the naive "declare the object-code-bank as a map region" approach is
STRUCTURALLY BLOCKED by the mixed build's AS-residual section granularity (proven by
experiment). S1.2's declarative-geometry realization needs a placer-level change, not a
byte-neutral map edit.** No map change committed — `sigil.map.toml` stays byte-identical;
native gates stay green (native_rom 2/2, native_full_rom 3/3).

## What was tried

Per design §2.3 (declare region geometry + section ordering; compute resume points),
the first fixed-geometry fact to migrate into `sigil.map.toml` is the 68k object-code
bank: `main.asm`/`engine.inc` `org $10000` … `if * > $20000 / error`. Added
`[[region]] object_code_bank lma_base=0x10000 size=0x10000` BEFORE the catch-all `rom`
region (so `region_for`'s first-match assigns object-bank LMAs to it, and `emit_rom`'s
`validate_section` enforces the `< $20000` budget from the MAP — the goal being that the
budget survives asl's `engine.inc` assert departing at Stage 2).

## Why it fails

`emit_rom` rejected it in both shapes:

```
section `sec73086` [0x11D7E,0x256DC) overflows region `object_code_bank` (ends 0x20000)
  — over by 22236 bytes   (plain; debug: sec73190 [0x11DE6,0x25744))
```

The AS residual (assembled with all gates ON) emits ONE contiguous section spanning
`[0x11D7E, 0x256DC)` — the object-bank tail (ObjDef_PathSwap onward) + the entire OJZ
level-data block region + the inter-content gap, ending exactly where `sonic_anims`
(`$256DC`) begins. So the object bank content and the post-bank level data are the SAME
AS section, and it CROSSES `$20000`. asl's `if * > $20000` budget is therefore an
INTRA-section checkpoint (asserted at the object-CODE end, mid-section), NOT a section
boundary. A map region can only validate whole-section containment, so it cannot express
"the code portion of this section ends before `$20000`."

## What S1.2 actually requires (scoped, not a quick edit)

To make declared region geometry enforceable, the mixed build must SPLIT the AS-residual
section at the declared boundaries (so the object-bank code, the level-data block, and
the sound/anim tail become distinct sections whose containment the map can check). That is
the same placer change the "computed resume points" half needs: order the sections by a
declared manifest and let each section's base/end fall out of placement + the AS-residual
holes, rather than pinning per-shape literals. Concretely:

1. Teach the mixed driver (or `sigil-frontend-as`) to emit the AS residual as sections
   split at the declared region boundaries (`$20000`, the level-data end, …), so no single
   section straddles a declared region. Byte-neutral (splitting a section changes no
   emitted byte — same LMAs, same bytes), but it changes the section GRANULARITY the
   linker sees, so it must be proven byte-identical both shapes.
2. Then the object-code-bank region (and further fixed regions) can be declared and
   `emit_rom`-enforced, and the per-shape resume `org`s (kill rows 6/58) can be computed
   from placement instead of pinned.

This is a real refactor with byte-identity risk (the linker's dup-symbol / section-order
handling must be re-proven under finer granularity), so it is NOT rushed under the S1.4
checkpoint budget — flagged for sequencing after the checkpoint-2 ruling. The map already
declares everything it safely can today (the `rom` catch-all + the `z80_moving_trucks_bank`
LMA≠VMA window); the object-bank/ordering/computed-resume growth is gated on step 1.

## Note

The pins-based per-section `.emp` placement (`native::emp_map_toml`) is UNAFFECTED and
correct — each `.emp` section IS its own clean region at its base; the granularity problem
is purely the AS RESIDUAL's boundary-crossing section, which the `.emp` side never touches.
So S1.4 and the native gates are independent of this and stand.

## RULING — DEFER as a STAGE-2 COMPANION task (overseer, 2026-07-30)

The section-split refactor would model the DUAL-STATE geometry — the contiguous AS
residual that Stage 2 DELETES. When the gate scaffolding + code twins go, the AS residual
collapses to small data islands, the section boundaries become natural, and the `$20000`
object-bank budget becomes enforceable as a map region over the `.emp` sections (SPEC2's
own end-state). Doing the linker-granularity change now is work against a corpse.

**STAGE-2 COMPANION TASK:** residual section-split + map placement ownership land WITH the
gate deletion, when the geometry they model becomes real. The map keeps what it safely
declares today (`rom` catch-all + `z80_moving_trucks_bank`); `pins.rs` remains the
placement source through Stage 2 — its values are frozen asl-derived constants (correct
while asl lives, which is now), and the re-pin tax dies with the twins regardless.

**Row-34 dependency:** post-flip, `repin`'s asl-`.lst` parsing is dead (no asl to parse);
placement MIGRATES pins→map rather than re-pinning. So the Stage-2 companion task also
retires `repin`'s listing-parse path and moves the placement facts into the grown map.
No further S1.2 code this stage.
