# Nothing measured what sigil accepts that asl refuses. Now something does.

2026-09-10. Row `NOTHING-MEASURES-OVER-ACCEPTANCE`, branch
`parcel/over-acceptance-gate`.

## The gap, stated as a property of the instruments and not as a complaint

Sigil had roughly 5,077 tests and not one of them could catch sigil ACCEPTING a
program `asl` refuses. Every gate measured one of two things: byte identity
against a known-good ROM, or that a corpus still assembles. Both are
one-directional. They go red when sigil gets STRICTER and stay green when it gets
LOOSER, because a program the corpora do not contain is a program no corpus gate
has an opinion about.

`2026-09-10-as-circular-split.md` section 5 is where this was written down, and
it was written down because that parcel nearly shipped the half-fix: a detector
that never fires would have passed all 5,034 tests then existing, removed the
pass cap, kept both corpora building, and read as success. Its section 6 recorded
three shapes sigil accepts and asl refuses, found by hand, one probe file at a
time.

## The design

Three committed artifacts and one runner.

`crates/sigil-frontend-as/tests/over_acceptance/probes/*.asm`, 88 minimal
programs.

`crates/sigil-frontend-as/tests/over_acceptance/asl_verdicts.txt`, generated by
`scripts/mint_over_acceptance_verdicts.sh`, recording what asl did with each.

`crates/sigil-frontend-as/tests/over_acceptance/ledger.txt`, hand-written, the
divergences currently tolerated and the reason for each.

`crates/sigil-frontend-as/tests/as_over_acceptance.rs`, nine tests, run by
`scripts/landing-run.sh` through `cargo test --release --workspace`.

asl is the frozen half (a binary of a fixed digest) and sigil is the moving half,
so asl's verdicts are committed and sigil is run live at test time. The gate
therefore needs no asl and runs anywhere, the same split `asl_snippets.rs` uses.

**The assertion is a set difference in both directions and never a count.**
`observed \ ledger` must be EMPTY, in each direction, and that is the hard gate.
`ledger \ observed` is computed and REPORTED and deliberately not asserted: a
ledger row that has started agreeing with asl is good news, and reddening on it
would make good news arrive as a defect and train the next reader to delete rows
to get green. A count would not do at all, because two populations can differ by
one member in each direction and total identically.

## The population, which is the part that decides whether any of this measures

**A corpus built from the shapes we already knew would be a gate that could not
come out other than green.** It would pass on the day it landed, pass forever,
and measure nothing, and it would read exactly like a working gate.

So the population is derived from asl rather than from our own findings. asl
ships its complete error catalogue in `as.msg` beside the binary, about 200
messages. The corpus is that catalogue filtered to the classes reachable from
68000 and Z80 source in the AS syntax sigil parses, one minimal probe per class:
82 probes, later 88.

**The 27 asl-ACCEPTED probes are not filler and the gate is unsound without
them.** Roughly half are the in-range twin of a refused probe (`dc.b 255` beside
`dc.b 256`, `bit 7,a` beside `bit 8,a`, a short branch in range beside one out of
range), which makes the corpus a boundary corpus and gives the over-refusal
direction something to measure. Without them a sigil that refused every program
would produce an empty over-acceptance set and read green.

**The three disassembly corpora were ruled out as a probe source on measurement
and not on taste.** s1disasm, s2disasm and skdisasm all assemble under asl, so by
construction they contain no asl-refused construct, and no sweep of them can
yield a refusal probe. The suggestion is a natural one and it cannot work.

Six probes come from a second source, and they are the exception that proves the
rule: `campaign-gap-ledger.md` rows 3 and 4 name expression-tier divergences
somebody had already measured and nothing watched. Four reproduce and are
ledgered; two do not and became live tripwires instead.

## What it found on its first run, before any ledger existed

Ten over-acceptances. Three were the known ones. **Three were not known to
anyone:**

| probe | asl | sigil |
|---|---|---|
| `dir_padding_not_on_off` | `#1520 only ON/OFF allowed` | accepts, and `padding maybe` silently means `padding on` |
| `expr_function_arg_count` | `#1490 wrong numbers of function arguments` | accepts, no arity check on user `function` calls |
| `save_missing_restore` | `#1460 missing RESTORE` | accepts, the save stack is never checked at end of unit |

The first is the worst-shaped: the over-acceptance is not merely a file that
should not assemble, it is a file that assembles with a layout flag set the wrong
way by a typo. `on_off()` in `eval.rs` treats every token that is not literally
`off` as ON, and `supmode` shares the helper.

Four more came from the gap ledger's row 4 and reproduced. Four over-refusals are
declared scope limits that refuse by name rather than mis-assembling silently.

**All fourteen are ledgered and none is fixed here.** Fixing changes what sigil
accepts, which is a separate decision with its own landing gate, and a parcel
that builds an instrument and acts on its first reading in the same breath has
conflated the two. Every one is booked in `campaign-gap-ledger.md`.

## Would anything go red? The headroom, and the number that answers it

Not the ledger's size. The number is how many probes are LIVE TRIPWIRES: probes
on which the two assemblers currently AGREE, where a change of behaviour reds a
gate.

**88 probes minus 14 ledgered divergences is 74 live tripwires**: 51 refused by
both, where sigil becoming looser goes red, and 23 accepted by both, where
becoming stricter goes red.

**And the ledger is not a way to buy green.** The hard gate can always be
satisfied by adding a row, and a gate whose only failure mode is fixable by
editing a text file beside it is a gate people edit. So
`feed_control_the_ledger_is_not_an_escape_hatch` floors both agreement counts:
ledgering a new divergence lowers one and reds a second gate, whose floor then
has to be moved by hand in the same diff, where a reviewer sees it beside the row
that caused it. A ledger COUNT would not do this, because it reads identically
whether a row was added for a new divergence or swapped for a retired one. This
already happened once in this parcel's own history: adding the four expression
probes moved `MIN_AGREED_REFUSALS` from 49 to 51 in the same commit.

## The oracle, and the rule that inverts here

The reference build is selected by `asl_ref.sh`, by md5
`61e672562465725a8c102288a7da9098`. Seven asl paths on this machine execute under
four distinct digests and every one prints `Macro Assembler 1.42 Beta [Bld 212]`.

**The standing rule is "an asl run carrying any error is not a source of values
for the lines that DID assemble". This corpus inverts its usual application.**
Most probes here are SUPPOSED to exit nonzero: a nonzero exit is the subject of
the measurement, not a fault in it, and `|| exit $?` after `asl_run` would be
exactly wrong. So the rule cannot be discharged by checking the exit status and
becomes instead: **never quote an emitted VALUE out of these runs.** The verdict
table records accept-or-refuse and the diagnostic text and nothing else, and no
expectation anywhere in the gate is a byte.

`ASL-GUARD-EXIT-STATUS`, which the row's brief and `OVERSEER-REFERENCE.md` both
described as open, is CLOSED and has been since `8e35bd94`: `asl_ref.sh` defines
`asl_run`, which reports and returns the exit status. `OVERSEER-REFERENCE.md` is
amended here, with the discharge stated rather than the caveat deleted: what
improved is that the guard now answers "did the run as a whole fail" as well as
"which program ran". It still does not answer "did the build answer THIS line",
and nothing does.

## Two measurement failures inside this parcel, both caught by a control

**The diagnostic extractor read the wrong stream.** asl writes diagnostics to
STDERR; the first minting script read stdout. All 82 rows came back with no
class and the table rendered a clean column of "no diagnostic", which is
indistinguishable from a corpus asl declines to number. It was caught by testing
the extractor against a known diagnostic, not by reading the result, which looked
finished. The script now refuses to write a table in which refusals exist and no
refusal carries a class.

**The em-dash sweep's own instrument was broken.** A `grep` for the two dash
characters, quoted through zsh, returned zero on the files AND zero on a planted
canary. The content was in fact clean, but that was not known until the sweep was
re-run under an instrument the canary proved could find one. A zero from a tool
that cannot find the thing is not a clean result, and the only thing that
separated the two readings was the canary.

## What is not covered

The corpus is one probe per refusal CLASS, not per instance within a class, so a
widening confined to a class already covered by a probe that still diverges the
same way is invisible. It reaches the AS front end's own paths; a construct
reachable only through `.emp`, or through `parse_num_atom` in the typed evaluator
(gap-ledger row 3), has no probe. And the 41 classes are the reachable subset of
about 200 catalogue entries: the rest belong to other CPU targets. Each of those
is a place to add probes, and the floors in the gate are what make adding them
visible rather than optional.
