## Design decisions

### D1 — module structure (buffers.emp)

`module engine.buffers in buffers`. Procs in twin order: Init_SpriteTable,
BuildStaticDMA, PlaneMapToVRAM, Enqueue_Dirty_Buffers. All pub except —
all four ARE pub (Init/Build: .asm callers; PlaneMap: exported API awaiting
its consumer; Enqueue: vblank.emp caller after file 2 — pub for the
cross-module call).

`use engine.structs.{DMAEntry, parallax_config}`,
`use engine.constants.{VRAM_SPRITE_TABLE, VRAM_HSCROLL_TABLE, PLANE_H_CELLS}`,
`use engine.vdp.{VdpTarget, VdpOp, vdp_comm, vdp_comm_delta, plane_loc,
dma_length, VDP_DATA, VDP_CTRL}` (+ the dma_source spelling per P8's
outcome).

### D2 — `.build_entry` call-then-fallthrough (brief obligation)

The twin: six `bsr.w .build_entry`, then the SEVENTH entry's setup falls
through into `.build_entry:` (lines 83-88), whose `rts` serves both as the
subroutine return and the proc end. The .emp spelling: `.build_entry` is a
plain LOCAL label inside BuildStaticDMA's body; six internal
`bsr.w .build_entry` (step 1 verbatim); the seventh setup block simply
precedes the label — the fallthrough is a fact of one proc body (the same
explicitness argument that chose dma_queue's shape (b), without needing
`export` since no external caller exists). → **PROBE P6** (binding class:
proc body with internal bsr to a local tail label that is also reached by
fallthrough, ending in the shared rts — contract/flag checkers must accept;
byte-parity vs AS). Step 2 converts `bsr.w` → `jbsr` and the relaxation
ladder may shrink in-range forward calls to bsr.s — twin lockstep + re-pin
(expected byte delta, measured at step 2, absorbed by the resume-org chain).

RESOLVED (P6): PASSED as-found — the local-tail call-then-fallthrough spelling lowers and byte-matches; step 1 uses it verbatim.

### D3 — queue_static_dma (macro-port rule; brief obligation)

Donor: `queueStaticDMA slotvar, queueend, entryvar` (engine/macros.asm:292,
7 call sites, ALL in Enqueue_Dirty_Buffers, ALL against the Critical
queue). Carries the CCR carry contract mirroring QueueDMA_Critical (carry
SET = dropped; `andi.b #$FE, ccr` / `ori.b #1, ccr` — frontend support
proven t20 P3) and feeds the dirty-bit retry protocol (clear ONLY on
carry-clear; a dropped enqueue leaves the bit set so the next VBlank
retries — the honest comments move to the fn header + call sites,
present-tense).

Macro-port rule answers:
- **Wrong-input scan**: the donor's 3-symbol interface lets a caller pass a
  MISMATCHED slotvar/queueend pair (Critical_Slot bounded by Important_End
  = a silently corrupt bound check). Types kill it by never exposing the
  pair: primary interface keys the QUEUE, not the symbols —
  `queue_static_dma(entry)` bound to the Critical queue (today's total
  demand; the two symbols live ONCE inside the fn). If a future consumer
  wants Important/Deferrable, the extension is a comptime enum arm mapping
  queue → (slotvar, end) INSIDE the fn — the pair stays unrepresentable at
  call sites. First-consumer duty satisfied: the inherited interface is
  entry-only; the call site reads `queue_static_dma(Static_Pal_Line0)`.
- **Guard upgrade**: the donor has no expansion-time guards; none die.
- **Taste gates**: call sites drop from 1 macro line + 3 args to 1 fn call
  + 1 arg; the AS twin keeps its macro spelling (lockstep is byte-level).
- **Parameter passing**: the entry symbol is a link-resolved RAM label
  spliced into `lea (entry).w, a2` position. → **PROBE P4** (binding class:
  comptime-fn argument carrying a GLOBAL link-resolved symbol, spliced into
  an EA operand + followed by a caller-side `bcs` consuming the spliced
  CCR result — the real Enqueue site shape). Fallback if global-symbol
  args don't pass: seven-site fold over a comptime list, or per-site
  splice-hole `{entry}` via Label-typed args as jt_slot does for locals.
- Kill row (same commit as the build): queue_static_dma ↔ macros.asm
  queueStaticDMA lockstep mirror; byte gates guard; dies with the twin at
  Spec 5.

RESOLVED (P4): PASSED — `queue_static_dma(entry: Label)` with global RAM symbols as args is the shipped interface (Critical-bound, entry-only; the slot/end pair lives once inside the fn).

### D4 — engine.vdp additions: dma_source / dma_length / vdp_comm_delta / plane_loc

Row-1052's predicted adoption. All four mirror AS `function`s
(engine/macros.asm:27-36). Macro-port rule: these are pure derivations
(no closed vocabularies, no guards, no unit confusion worth a newtype at
current demand — `plane_loc(width, col, row)` keeps int params; the
VramAddr-class results are A4-i-gated, LOG-not-type per the item-13 rule).
Derivations verbatim; byte gates bind the folds:

- `pub comptime fn dma_length(bytes: int) -> int` = `(bytes >> 1) & $FFFF`
- `pub comptime fn vdp_comm_delta(addr: int) -> int` =
  `((addr & $3FFF) << 16) | ((addr & $C000) >> 14)`
- `pub comptime fn plane_loc(width: int, col: int, row: int) -> int` =
  `((width * row) + col) * 2`
- `dma_source(addr) = (addr >> 1) & $7FFFFF` — **the hard one**: every
  buffers.asm call site feeds a LINK-TIME RAM address (Palette_Buffer,
  Sprite_Table_Buffer, Hscroll_Buffer), so a comptime fn cannot fold it.
  → **PROBE P8** (binding class: link-time value expression with `>>` and
  `&` over `extern()` — `equ PAL_SRC = (extern("Palette_Buffer") >> 1) &
  $7FFFFF` class — through the emp pipeline into a `move.l #imm` cell,
  byte-parity vs AS computing the same fold). If the link-expression
  grammar lacks shift/mask, the feature is DEMANDED (TDD-first). The .emp
  spelling then: a comptime dma_source stays for comptime addrs (none
  today), and the buffers sites ride file-local equs
  (`equ SRC_PAL = (extern("Palette_Buffer") >> 1) & $7FFFFF`-class) or —
  if P8 passes with fn-over-equ composition — `dma_source` applied to an
  equ value. Spelling decided by P8's outcome.

RESOLVED (P8): PASSED — link-expressions fold `>>`/`&` over extern(). Shipped spelling: `pub comptime fn dma_source(addr: int) -> int` joins engine.vdp for comptime addrs, and the three RAM-source sites ride file-local equs (`equ SRC_PAL = (extern(\"Palette_Buffer\") >> 1) & $7FFFFF`-class) whose derivation mirrors dma_source — each equ site-commented as the link-time arm of the same derivation (the comptime fn cannot see link values; row-1004 boundary).

### D7 — vblank.emp structure

`module engine.vblank in vblank`. Procs in twin order: VBlank_Handler
(pub — vectors.asm dc.l), VInt_Level (pub — boot.asm/ojz move.l #imm),
VInt_Lag (module-internal, non-pub), VSync_Wait (pub — the flip +

  hblank.emp HBlankHandler convention (full movem save/restore + rte;

  — jsr STAYS) with `type VBlankHandler = proc () clobbers(d0-d7/a0-a6)`
  (the game_loop GameState honest-⊤ pattern). Whether VInt_Ptr itself
  grows a typed-pointer bless is the brief's step-4 adjudication
  (stores happen in .asm boot/test code — likely documentary; demand data
  decides there, not here).
- `VInt_Level () clobbers(d0-d3/a0-a3/a5-a6)` — union of Flush_VDP_Shadow
  (d0-d3/a0-a1), Enqueue_Dirty_Buffers (d0/a1-a2), VInt_DrawLevel
  (d0-d1/a0/a5-a6), Process_DMA_Critical (a1/a5), Vscroll_Write (d0/a0/a5),
  Process_DMA_Important/Deferrable (d0-d1/a0-a3/a5), Read_Controllers

- `VInt_Lag () clobbers(d0-d3/a0-a2/a5)` — Flush + Enqueue +
  Process_Critical + Vscroll_Write + Read_Controllers union.
- `VSync_Wait () clobbers(d0)` — the pinned extern contract EXACTLY.
