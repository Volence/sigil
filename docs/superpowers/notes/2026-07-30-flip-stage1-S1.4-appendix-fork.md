## What the pipeline is (verified empirically against the prebuilt `tools/convsym`)

`build.sh:169-175`: after `p2bin`, if `${ROM_NAME}.lst` exists,
`convsym ${ROM}.lst ${ROM}.bin -input as_lst -range 0 FFFFFF -exclude -filter "z[A-Z].+" -a`
APPENDS the MD-Debugger deb2 table at `EndOfRom` and bumps `$1A4` (ROM-end pointer); then
`fixheader` re-checksums `$18E`. The full file = assembled ROM + deb2 appendix.

**convsym `as_lst` reads the `Symbol Table (* = unused):` SECTION of the `.lst`** (not the
body listing lines — a body-only `.lst` fails `FATAL: Coudn't find symbols table`). From
that section it takes **only `C`-marked (code/address) rows** — equate (`-`) rows are
excluded, and the unused `*` flag is IRRELEVANT (both used and unused `C` symbols are
included). `-range 0 FFFFFF` then keeps only symbols with value ≤ `0xFFFFFF`, which
**excludes every RAM symbol** (`$FFFFxxxx`, shown by asl as `FFFFFFFFFFFF____`). The
`-exclude -filter "z[A-Z].+"` filter matches zero Aeon labels (confirmed) but is passed
verbatim. Output symbols are address-sorted inside the deb2 table.

Net: the appendix is a pure function of the **set of `C` symbols with address ≤ 0xFFFFFF —
their NAMES and ADDRESSES only**. To reproduce asl's appendix byte-for-byte, sigil's `.lst`
symbol-table section must present that exact name+address set.

### Positive-control CORRECTION (design §3.3 was wrong)

The deb2 header is `de b2` followed by **data-dependent** bytes — observed `de b2 04 02`
in the real ROMs but `de b2 00 1a` / `de b2 00 06` in synthetic runs (the 3rd/4th bytes
encode the packing/offset, not a fixed magic). **The assert-PRESENCE control must check
`de b2` (2 bytes) at `EndOfRom` + a non-trivial size band, NOT `de b2 04 02`.** A silent
convsym failure (`2>/dev/null || true`) still yields an appendix-less ROM = hard FAIL.

### The name divergence is four structural classes (not a small patch)

1. **Inline-`asm{}`-block locals (the bulk).** sigil scopes locals inside inline asm blocks
   to a synthetic block counter: `asm14.abs`, `asm2.clamp`, `asm34.cell`. asl scopes local
   labels to the **enclosing global label**: `Air_LandState.abs`, `Camera_Update.clamp_x`,
   `Collision_ProbeLeft.cell`. The enclosing-global name is DISCARDED by sigil's mangling
   (unrecoverable in a listing-side translation), AND the leaf differs too (`clamp` vs
   `clamp_x`, `piece_loop` vs `piece_loop_yf`). Hundreds of labels across collision/player/
   camera/touch/DMA modules.
2. **Comptime-table-generated labels.** The anim-table DSL emits internal names
   `__offsets$games.sonic4.sonic_anims$Ani_Sonic$Balance` / `__align$…$0` for what asl's
   `.asm` calls flat `Ani_Sonic_Balance`, `Ani_Sonic_End`. Different naming model entirely.
3. **Global renames** — the `.emp` chose different names than the `.asm` twin:
   `Cold_Boot`→`EntryPoint` (+15 locals), `ErrorHandler`→`ErrorHandlerBlob`,
   `Ground_Move`→`Ground_Move_Cap` (+22 locals), `QueueDMATransfer`→`QueueDMA_Deferrable`,
   `Perform_DPLC_Deferrable`→`asm3`, `TestEmitter_Main.particle_desc`→`emitter_particle_desc`,
   `Warm_Boot.*`→`EntryPoint.*`, etc.
4. **~50–72 genuinely-extra sigil labels** asl never emits (`Process_DMA_Critical.drain_1..8`,
   `asmN.wait_z80`, `TestArt_Ring`, `EmitterPositions`) — these would ADD deb2 entries.
   Plus **3 truly-absent** asl locals sigil doesn't produce (`Perform_DPLC.done`,
   `Player_SlopeRepel.speed_abs`, `Process_DMA_Critical.drain_end`).

None of these is translatable listing-side: classes 1–2 need information sigil's naming
model throws away; classes 3–4 are genuine label-name choices. Matching asl exactly would
require (a) changing how sigil mangles inline-asm locals to asl's enclosing-global scheme
AND matching leaf names, (b) changing the anim-table DSL's label naming, and (c) dozens of
`.emp` global/local renames — a sigil-compiler + broad-aeon effort measured in weeks, all
to match a toolchain that LEAVES at Stage 2.

## The fork — for the overseer to rule

- **Option A (RECOMMENDED) — sigil-canonical appendix + re-frozen golden.** The appendix is
  MD-Debugger metadata, not ROM behavior. Redefine S1.4's bar: (i) assembled-ROM bytes ==
  asl (ALREADY proven, S1.1), (ii) sigil's listing → `tools/convsym` produces a VALID,
  self-consistent, deterministic appendix (assert-PRESENCE `de b2` + size band + Oracle
  `LoadFromAsListing` / `s4budget.py` consumers parse it), and (iii) the FROZEN GOLDEN is
  **sigil's own full file** (captured now under asl-live provenance, re-verified at Stage 2).
  The `native == asl` clause holds for the assembled ROM; the appendix golden is sigil's.
  This matches the design's own observation (§5/§6.2) that post-flip goldens are re-frozen
  to sigil, and it is a stable/reproducible target (convsym is deterministic).
- **Option B — reconcile names to asl.** Make sigil emit asl-identical symbol names:
  sigil-compiler inline-asm-local naming change + anim-table-DSL label naming + dozens of
  `.emp` renames. Byte-neutral to the ROM but large, touches the compiler, and is arguably
  pointless (asl departs). Not recommended.
- **Option C (rejected) — a convsym `-filter` restricting to the agreed set.** Not viable:
  the divergent set is a large regex-inexpressible fraction, and it still wouldn't match
  asl's appendix (different symbols packed).

Under Option A the rest of Stage 1 proceeds: wire `emit_listing` to derive the symbol set
from the link table + drive convsym + assert-PRESENCE (ruling-independent infrastructure),
then capture sigil's own full-file goldens for all six ROMs.
