## THE SEAM RULING (overseer-cut; step-0 verifies, does not re-litigate)

boot.asm splits at the `BootData` label: **CODE → boot.emp; the ENTIRE
BootData table (movem preloads, VDP reg bytes, fill command, Z80 blob
include, PSG bytes, post-DMA commands) stays .asm — the .asm-data-tail
option.** Concretely, in the aeon tree:

- Split the twin: `engine/system/boot.asm` keeps the code
  (EntryPoint → `bra.w GameLoop`); NEW `engine/system/boot_data.asm`
  carries `BootData:` → `BootData_End` verbatim (including the
  SOUND_DRIVER_ENABLED-selected include and both aligns).
- engine.inc gate (standing idiom, vdp_init model at engine.inc:88-101):
  ```
  ifndef SIGIL_EMP_BOOT
      include "engine/system/boot.asm"
  else
      org <per-shape BootData start>
  endif
      include "engine/system/boot_data.asm"
  ```
  The data tail is included in BOTH arms — the mixed splice window covers
  ONLY the code, so no splice ever crosses the nested source-include
  boundary (recon confirmed no prior arm has, and none will now).
- **The split commit comes FIRST, alone, byte-verified**: restructure the
  twin (boot.asm → boot.asm + boot_data.asm, engine.inc include added),
  prove BOTH canonical CRCs unchanged, commit before any .emp lands.

Grounds (each verified against the repos this session):

1. **`.emp` categorically cannot express the seam's center**: no source
   `include` exists in the language (spec §3.2; zero hits in the corpus;
   frontend has no such construct) — `embed()` is binary-only. The inline
   `cpu z80 / phase 0` source assembly is AS-frontend machinery, proven
   en-bloc by the whole-ROM gates.
2. **Every binding class the code side needs is ALREADY PROVEN:**
   - `lea <asm-data-label>(pc)` from .emp: **vdp_init.emp:27 already does
     `lea BootData_VDPRegs(pc), a0` into this exact table** (pinned at
     repin.toml:486-488). BootData already has a live .emp consumer
     relying on it staying .asm-side.
   - AS-computed const in .emp: `extern("SYMBOL")` link-time value reads
     (sound_api.emp:45-65; t22 CSELF class) — the `Z80_SOUND_SIZE` import
     spelling.
   - Game-supplied macro: game_loop.emp:33-43 mirrors sonic4's
     gameDebugTick expansion under comptime flags with a kill row tying
     the .emp to the macro body — gameBootHook copies this exactly.
   - `.asm → .emp` vector reference: vectors.asm:9 `dc.l EntryPoint` is
     the t21-proven IRQ6 class (vectors.asm:38 `dc.l VBlank_Handler`).
3. **The Z80 ladder is Volence-deferred** (2026-07-24 jot: T1/T2/T3 — "we
   can do it later"). An embed-.bin-twin would need a second
   source-of-truth for the blob bytes + `Z80_SOUND_SIZE`, adds a build
   artifact + staleness hazard (real campaign scars), and jumps the
   deferred queue for zero byte benefit.
4. **chained-section split severs the table's own strongest coupling**: the
   `(a5)+` walk is ONE sequential cursor over the whole table; a module
   boundary mid-cursor makes the layout unauditable. The code↔table-head
   coupling that remains (movem widths/order ↔ table head) is guarded
   instead by an **AS-side layout-assert wall in boot_data.asm** (both
   assemblers run it — sigil assembles the .asm universe too): at minimum
   `(BootData_VDPRegs-BootData) == 3*2+5*4`, the blob-start offset, and
   post-blob evenness. Step-0 finalizes the list.

**vectors.asm rides the same ruling: pure `dc.l` table (error handlers are
still .asm-owned debug-trio symbols) — stays .asm, NOT a t23 port target.**
Its `dc.l EntryPoint` (reset PC) flips to the .asm→.emp class at merge; the
mixed arm proves it resolves to the pinned EntryPoint address.

## THE UPSTREAM-SLIDE BAR (gap-ledger row 1257-1268 — binding)

Boot sits UPSTREAM of every gated region (first include in
`__BUDGET_ENGINE`, engine.inc:87). **Any boot byte-change slides every
engine base, BootData/`BootData_VDPRegs`, the Z80 blob anchor
`REGION_A_LMA`, and every downstream pin.** The phase2.5-c5 −0xA slide is
the exact playbook; row 1257 records the fixture classes that surfaced.
Therefore:

- Step-1 is byte-identical as always — no slide.
- Step-2/loop byte-changing improvements in boot are IN-SCOPE (the
  better-not-SAME law stands; skipping is a logged decision, never a
  silent default) but are **BATCHED INTO ONE WAVE** with ONE re-pin, and
  that wave's gate includes the **row-1257 sweep: every hardcoded
  engine-address fixture in `crates/` over `[boot, $10000)`**, plus
  `REGION_A_LMA` and the mixed_dac_rom map bases/windows, plus the
  standing 5-site ripple (engine.inc orgs / mixed_dac_rom.rs /
  repin_pins.rs hand-edits; repin does only pins.rs).
- Known shrink candidates are SMALL (e.g. `move.w #0,(Frame_Accumulator).w`
  → `clr.w`, −2): adjudicate each at step 2/3 on the record; the slide is
  priced once by the batching, not per-item.
- The t22-ratified step-2 checklist line applies if any relaxation turns
  shape-divergent (twin rides ifdef widths, .emp stays bare).
