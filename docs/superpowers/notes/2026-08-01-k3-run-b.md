## §2 — Placement mechanics (the K2 BootData_End lesson, ×3)

Each new native section needs a **frozen boundary key** — an `.emp` ROM section gets
a cosmetic base 0 from `place_sections`, so a key-less section sorts to the FRONT and
collides. Proven empirically: before seeding, the build died with
`packed base 0x5990 for section sec256 overruns its provisional 0x100` (the header
section overrun — the keyless assets/bg_anim sections had sorted ahead of it).

- `OJZ_Sec0_Blocks` already a frozen key (the old AS run-B head) → `sec_block_blobs`
  places for free.
- `OJZ_Palette` + `BgAnim_Table` seeded into the **4 sonic4** frozen tables (s4,
  s4_debug, config_a, config_b — demo has no OJZ data), computed from the invariant
  offsets `OJZ_Palette = OJZ_Sec0_Blocks + 0xB08A` and `BgAnim_Table = Map_TestObj − 2`,
  then CONFIRMED by `derive_offcanon` (which auto-emits one head label per section).
- Pins `SEC_BLOCK_BLOBS` / `OJZ_ACT_ASSETS` / `OJZ_BG_ANIM` — `repin` reported **0
  pins changed** (the golden-extraction seeds were exact).
- `repin.toml` regions (start/end = next placement; NO `gate` — these have no AS
  twin: act_descriptor.asm's includes were DELETED, not holed out).
- `map.toml` order rows `OJZ_Palette`, `BgAnim_Table` (K1 union-order validation:
  each section's min-offset-label id must be in `order` — green).
- Registry: three `ModuleSpec`s (native.rs); demo_registry filters them out (engine-
  only), so demo/demo_debug are untouched.
