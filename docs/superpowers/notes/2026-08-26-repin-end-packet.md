# REPIN-END packet — `repin.toml` region ends measure a section, not an allotment (2026-08-26)

Branch `fix/repin-end` (sigil), from master `bbcc0cb0`. Sibling of SECTION-ROW
(`2026-08-26-section-row-packet.md` §4, which named this parcel); design context
`design/derived-layout:docs/superpowers/notes/2026-08-26-derived-layout-design.md` §0
("a gap between labels is an allotment, never a proven-free hole"). No ROM byte moves;
nothing under `golden/` or `provenance.toml` changes; `pins.rs` changed only through
`repin`.

## 1. The failure

`repin` measures a region as `end − start`, both LABELS. When `end` is the NEXT
section's head, it sits past the owning section's last byte on an alignment boundary,
and the successor's placer pad enters the pin. Live instance: `act_descriptor`
(`start = "OJZ_Act1_Descriptor"`, `end = "OJZ_Sec0_Blocks"`) pinned `plain_len 0x27C /
debug_len 0x280` while the section emits `0x28 + 9 × 0x42 = 0x27A`. Both
`act_descriptor_port` gates failed on LENGTH alone with every one of the first 0x27A
bytes equal to the reference (the aeon lane's probe; reproduced here — §5).

## 2. Design chosen: `section:<name>` boundaries (the SECTION-ROW spelling)

`crates/sigil-harness/src/repin.rs`:

| spelling | `start` resolves to | `end` resolves to |
|---|---|---|
| `"Label"` (unchanged) | the label's placement address | the label's placement address |
| `"section:<name>"` | the named section's LMA | the named section's OWN one-past-end, `lma + image_len` |

`<name>` is the `module … in <name>` section name — the same key the map's `order` rows
take (SECTION-ROW). The listing carries a section table (`Listing::with_sections`,
`native::section_extents`); the end derivation is `native::section_end` = `lma +
image_len`, the ONE function now behind both synthesized `<Base>_End` markers
(`derive_frozen_table`, `sigil_native_symbol_listing`) and the `section:` end — no
second derivation was invented.

Why `section:` at `end` means the section's OWN end and not (as the SECTION-ROW packet
sketched) the named section's LMA: naming the SUCCESSOR at `end` is the defect being
closed — its LMA is the pad-inclusive allotment. A region that wants "up to where the
next section starts" already has the bare-label spelling; a region that wants "my
bytes" now has `section:<me>`. The two spellings are therefore never synonyms, and the
doc-comment in `pins.rs` shows which one a pin was measured by.

Why not a bare `"section-end"` keyword: it would be a third spelling with no name in
it; `section:<name>` self-documents the owner and is greppable against `map.toml`.

Bare labels keep working unchanged (the ~80 end-is-next-placement regions are
byte-for-byte the same pins — §4). A bare `end` that measures placer pad past the
region's last section byte is now DETECTED and NAMED per shape
(`Listing::pad_past_content` → `Resolved.warnings`, printed by the `repin` bin as
`repin: warning: region \`X\` (plain): end \`L\` measures 0xN byte(s) of placer pad past
section \`S\`'s last byte (… vs …); … spell \`end = "section:S"\``). It is a warning, not
an error, because 79 existing pins carry that pad by convention and their port gates
tolerate it; making it fatal would block every regen until a manifest-wide conversion
(ledgered, §7).

Loud on unmeasurable: `section:<unknown>` → `region \`x\` end: section \`unknown\` not
found in the resolved layout`; a listing with no section table → `\`section:desc\`: the
listing carries no section table … the spelling cannot be measured`; a name matching
two sections → `ambiguous`. A table-less listing still measures bare labels exactly as
before and stays silent (nothing to judge).

Scope: the `section:` spelling is honoured in the two-shape region arm. The
`debug_only` / `plain_only` arms keep label-only boundaries (a `section:` there fails
loud as an unknown symbol, naming it) — no live region needs it; extend when one does.

## 3. `repin.toml` edits

- `act_descriptor`: `end = "OJZ_Sec0_Blocks"` → `end = "section:act_descriptor"`.
- `scene_registry`: `end = "EditorSceneBinding_OJZ_Act1_Sec0"` → `end =
  "section:scene_registry"`. **Finding:** the defect does NOT apply there today. The
  baseline pad scan (§4) did not flag `scene_registry` in either shape; with the
  `section:` spelling the pin is UNCHANGED at `0xACE / 0xACE` — the generated
  successor's head sits flush against the registry's last byte (no pad, both shapes).
  The aeon lane's "0xB1C vs 0xACE" was the pre-repoint state recorded in the region's
  own comment (`OJZ_TestRaster` end, refused by the align-pad tolerance), not the
  current pin. The re-spelling is still right: the content-derived label
  (`tools/effects_gen.py`'s first emitted symbol) rots the way the `order` row did, and
  the section name cannot. A re-spelling, not a re-measure.
